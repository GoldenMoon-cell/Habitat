## 一 · 等你自己验证的

**这些要真人跑一遍才知道，代码层面已经做完。**

### 1.1 记忆提取率

**为什么没在代码里改**：核对过 —— 提取器工作正常。
文件里那条「这条我要拿回来改」（9 字、含「我」）被正确提取了。
真实的我方消息只有 3 条，全部**正确地没有被记**。

**所以不是规则坏了，是没有真实对话。**

**怎么验**：跟她聊 10 轮，刻意覆盖三类 ——

| 说什么 | 该记成 |
|---|---|
| 「我不吃香菜」 | `偏好` |
| 「今天累死了」 | `情绪` |
| 「我在杭州上班」 | `长期` |

**判据**：

| 结果 | 结论 |
|---|---|
| 三类都记上 | ✅ 提取器正常，这条关闭 |
| 偏好/身份记上，情绪漏 | ⚠️ 情绪门槛（≥8 字）偏严，回来调 |
| 三类全漏 | ❌ 真有问题，重开 |

### 1.2 右键提示

第一次发消息后应该弹一次「右键 · 消息上可以复制、引用、朗读」，之后不再弹。

## 三 · 还没想清楚的三件事

**这些不是"待做"，是"没想明白"。** 写在这里是防止忘掉。

### 3.1 立绘接不接

素材已备，代码没接。**问题是接了之后，她"长什么样"就固定了** ——
而现在设计里，她的形象是从对话里长出来的。

### 3.2 语音

**已经做了** —— 见 `src/lib/tts.ts`，三档：`off` / `native`（系统自带，零配置）/ `cloud`（OpenAI 兼容）。

**还没想清楚的是"流式"**：现在的实现是「POST 一次 → 等 2 秒 → 拿到整段 mp3 → 播」。
低延迟语音需要流式（边生成边播，第一个字 200ms 出来），那是 WebSocket，不是一次 HTTP。

**这个问题会在下面 §五 的时间点变成必须回答的。**

### 3.3 「她主动找人说话」

现在只有你说话她才回。**如果她能在你不在的时候发消息** ——
那需要后台任务，而这是个 Electron 单窗口应用。

## 五 · 2027-01-06 · OpenAI TTS 关停

**这是个有确切日期的事，不是"也许"。**

### 已经确认的事实

| | |
|---|---|
| **关停日** | **2027 年 1 月 6 日** |
| **关停的模型** | `tts-1` · `tts-1-hd` · `gpt-4o-mini-tts` |
| **指定的替代品** | `gpt-realtime-2.1-mini` |
| **替代品的端点支持** | **`v1/audio/speech` → Not supported** |

来源：
- [OpenAI · Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech)
- [mixed-news · OpenAI's named TTS replacement lists v1/audio/speech as not supported](https://mixed-news.com/en/openai-tts-replacement-gpt-realtime-2-1-mini-audio-speech-not-supported/)

**关键**：不是端点被删，是**端点还在但没有模型能走它**。
这比删掉更麻烦 —— 它不会给你 404，会给你一个空壳。

### 对生境的影响：现在为零

生境发的是**格式**，不是"调 OpenAI"：

```
POST /v1/audio/speech
{ model, input, voice, response_format }
```

**这不是"调 OpenAI"，这是"说一种普通话"。谁听得懂就发给谁。**

2027 年 OpenAI 不听了 —— 还有六家在听：

| 服务 | 状态 |
|---|---|
| SiliconFlow 硅基流动 | ✅ OpenAI shape |
| Fish Audio | ✅ `/compat` 层 |
| LiteLLM | ✅ 网关 |
| new-api / one-api | ✅ 网关 |
| doteb | ✅ 转 ElevenLabs / Gemini |
| Paxa | ✅ 专做这个 —— 「Point the OpenAI SDK at Paxa, and your model and voice names keep working」 |

**有人在赌「OpenAI 格式会成为事实标准，而 OpenAI 自己不做了」。**

### 什么时候该动

**不是按日期动，是按条件动。**

- [ ] **如果 2027 年之后还有 ≥1 家服务支持 `/v1/audio/speech`** → **不动**
- [ ] **如果全部服务商都迁到 Realtime（WebSocket）** → **加一条流式通道**
- [ ] **如果出现了新的统一标准** → **加一个模式**（和现在的 `native` / `cloud` 并列）

**判断方法**：每年 12 月查一次 OpenAI 的 deprecations 页 + 上面那六家的文档。
如果六家里有三家以上宣布弃用这个格式 —— **那就该动了**。

### 到时候的三条路

**① 换一家还在支持的**（最省事）
```
只改默认 Base URL 和模型名。代码不动。
```

**② 加 Realtime 通道**（工作量大）
```
WebSocket + 流式音频解码。
好处是延迟从 2 秒降到 200 毫秒 —— 那才是"她在说话"的感觉。
坏处是整条播放链路要重写。
```

**③ 退回系统语音**（兜底）
```
native 那一档永远在。声音机械，但不会因为任何服务商的政策而死。
```

**这也是为什么当初做 `native` 是对的** ——
**它是唯一一个不受任何第三方政策影响的档位。**

### 现在不要做的

- ❌ **改默认模型名** —— `tts-1` 还能用到 2027-01-06。改成别人不认的名字反而会坏
- ❌ **现在写 Realtime 支持** —— 一年多以后的事，现在做是猜
