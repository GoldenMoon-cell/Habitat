# 操作手册

## 配 API

**设置（`Ctrl+,`）→ API 接入**。

| 字段 | 填什么 |
|---|---|
| Base URL | 官方：`https://api.deepseek.com/v1`<br>中转站：通常也是 `/v1` 结尾 |
| API Key | `sk-...` |

**不要填 `/chat/completions`** —— 程序会自己拼。

点「测试连接」会拉模型列表。**浏览器里大概率报 CORS**（DeepSeek 不回 CORS 头），直接点保存就行，**对话时走主进程不受影响**（仅 Electron）。

### 为什么浏览器里对话会失败

渲染进程是浏览器环境，跨域请求要过 CORS preflight。远程 API 不回 CORS 头 → 被拦。

**Electron 主进程是 Node，没有同源策略** → 走 `llm:chat` 通道正常。

所以：**配 API 可以在浏览器里做，真实对话要用 `npm run desktop`。**

## 改角色的模型

模型名对不上时会报「Model Not Exist」。两种改法：

**控制台**（`` Ctrl+` ``）：

```
ai model 澜汐 deepseek-flash
ai model 澜汐                    # 不带参数 = 查询当前
```

点 chip 一路点到底也行：`ai` → `model` → `角色` → `模型名`。

**注意**：`deepseek-flash` 是官方别名，会自动指向最新版（当前 `deepseek-v4.1-flash-1017`）。**不要写死版本号。**

## 控制台指令

`` Ctrl+` `` 唤起。支持点 chip，也支持手打。

**`help` 显示 17 条，另有 5 条隐藏的（共 22 条）。**

`help` 和 Tab 补全**是同一张表生成的**（`SPECS`），所以永远一致。

`net` / `dsh` 不在里面 —— 它们只会回「没有这个模块」，不该教用户学。

### `ai` · 角色

| 指令 | 作用 | 需要造物主 |
|---|---|---|
| `ai list` | 列出所有角色的状态 | — |
| `ai mute <角色>` | 置为 offline（头像是灰的） | — |
| `ai online <角色>` | 恢复 online | — |
| `ai reset <角色>` | 清空上下文占用 | — |
| `ai model <角色> [模型名]` | 改 / 查模型 | — |
| `ai inject <角色> <情绪>` | **强设情绪**（同时改显示标签和动态心情） | **✅ 需要** |

**`ai inject` 为什么需要造物主**：六维是**底稿**（她本来就长这样），心情是**结果**（由对话、时间、亲近度算出来的）。手动塞一个心情 = **伪造她此刻的感受**。

**`ai model` 为什么不需要**：换的只是「谁在念这些」，六维、记忆、人设全没变。**那是配置，不是篡改。**

`<情绪>` 可选：`雀跃` / `开心` / `平静` / `无聊` / `低落` / `委屈` / `生气`

**角色名四种写法都认**：

| 写法 | |
|---|---|
| `ai mute DeepSeek` | 名字 |
| `ai mute deepseek` | 大小写无所谓 |
| `ai mute @DeepSeek` | handle |
| `ai mute p1` | id |

**打错名字时**：会列出当前所有角色。

**如果那个名字改过**：会提示「她改名叫「月见」了」（记在 `3w:name-history` 里，会一路查到底）。

### `sys` · 系统

| 指令 | 作用 |
|---|---|
| `sys status`（或 `status`） | 资源与运行状态 |
| `sys list` | 可注入故障的区块列表 |
| `sys glitch <target>` | 让某个区块进入故障态 |
| `sys restore` | 清掉所有注入的故障 |

### `log` · 事件流

| 指令 | 作用 |
|---|---|
| `log pause` / `resume` | **暂停 / 恢复自动滚动**（日志本身不会停 —— 它是事实记录） |
| `log clear` | 清空 |

### `api` · 接口

列出你配的凭据（从 `3w:credentials` 读）：名字 · 模型数 · host。

`net` / `dsh` 会告诉你**没有这个模块** —— 这个软件不代理网络流量，也没有后端 agent 通道。

### 隐藏的五条

**不在 `help` 里，不在补全里。** 只能靠知道它们存在。

| 指令 | 作用 |
|---|---|
| `creator [` + `creator confirm` | 进造物主模式（要签两次） |
| `sim` | 回推演模式 |
| `time [+N]` / `time 0` | 拨时间（只拨流逝，不拨历史） |
| `doom <角色> <天数> [--tell]` | 判死期 |
| `graves` | 打开墓碑电子册 |

### 其他

| 指令 | 作用 |
|---|---|
| `engine` | 引擎等级 |
| `clear` | 清空控制台输出 |
| `help` / `?` | 全部可见指令（17 条） |

## 排错

### 聊天区显示「模块离线」

点「重新挂载」。如果反复出现，F12 看具体 `TypeError`。

**这通常不是偶发** —— 是某个数据字段是 `undefined` 被当数组用了。把错误贴出来能定位。

### 回复永远是同几句话

**在走 mock**。查标题栏：

```
MOCK · 未连接 API     ← 假的
```

原因：
- 没配 Key
- 或配了但角色的模型没有对应凭据

### 模型说「我不记得之前说过什么」

按可能性排序：

1. **上下文超了** → 查头部的 `CONTEXT 41/128k`。满了会从最旧的开始丢
2. **清空过对话** → 右侧「记忆活性」显示「静默」
3. **群聊和私聊是隔离的** → 群里说的私聊里不知道

### 她说话像另一个人

三个地方会影响：

| 位置 | 影响什么 |
|---|---|
| `tagline`（一句话） | **模型读这个**（`你是「澜汐」，${tagline}`） |
| `style` / `social` / `trigger` | 说话方式 |
| 静态四轴 | 语气倾向 |

**改完要刷新页面。**

### 「老是深夜好」这类固定开场白

prompt 里有「该这样做」的例子被照抄了。查 `src/lib/prompt.ts` 里带引号的正向举例。

## 语音

设置 → 语音，三档：

| 档位 | 要配什么 | 声音 |
|---|---|---|
| **关** | 无 | 只有提示音 |
| **系统** | **什么都不用配** | 机械，但立刻能听 |
| **云端** | Base URL + API Key | 好听 |

**「系统」那一档是零配置的** —— 选上就能听见她说话。

云端走 OpenAI 的 `/v1/audio/speech` 格式。已知能用的：

| 服务 | Base URL |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| SiliconFlow | `https://api.siliconflow.cn/v1` |
| Fish Audio | `https://api.fish.audio/compat/v1` |
| 自建网关 | 你自己搭的地址 |

**Base URL 填到 `/v1` 就行；也可以直接填完整路径（以 `/audio/speech` 结尾）。**

**注意**：不是所有 TTS 服务都兼容这个格式。Azure / 阿里 / 腾讯 / 火山要各自签名，用不了。**要么换一家，要么搭个 one-api / new-api 网关转一道。**

### 音色

角色自己的音色在「人格」tab 里填 —— 空着就用设置里的默认值。

两种模式各自解释这个字段：

- **云端**：直接传给服务商（`alloy` / `nova` / Fish 的 `reference_id`）
- **系统**：模糊匹配系统音色名（填 `Huihui` 命中 `Microsoft Huihui - Chinese (Simplified, PRC)`）

### 朗读

**不自动播。** 每条消息旁边一个 🔊，点才念。

点 → 念，再点 → 停。

## 数据在哪

**运行时在 `localStorage`，落盘在 `%APPDATA%\habitat\data\`。**

桌面上 origin 恒为 `app://habitat` —— 跟端口无关，所以不会因为 1420 被占就换个身份、把数据分到另一份 localStorage 里。

**磁盘上的文件**：

```
C:\Users\<你>\AppData\Roaming\habitat\data\
  current.json             每次改动后 2.5 秒覆盖写
  backup-2026-10-24.json   每天第一份，保留最近 14 天
```

两个文件内容一样，是同一份 `DataBundle`。`current.json` 永远是最新的，`backup-*` 是当天早上那份 —— 当天改坏了还能回去。

**启动时会自动把文件补回 localStorage**（`bootstrapRestore`）。语义是**填空不覆盖**：

| 情况 | 结果 |
|---|---|
| localStorage 空（清了缓存 / 换了 origin） | 从文件补回来 |
| localStorage 有值 | 保留，文件不动 |
| 从没存过文件 | 正常启动，无动作 |

所以「清空对话」不会被昨天的备份复活 —— 因为清空写的是空存档 `{"v":1,"threads":{}}`，那算「有值」。

`localStorage` 里的 key：

| key | 内容 |
|---|---|
| `3w:threads` | 对话记录 |
| `3w:personas` | 角色档案（含四轴） |
| `3w:groups` | 群 |
| `3w:engine` | 引擎配置 |
| `3w:credentials` | **API 凭据（明文）** |
| `3w:dynamic-v1` | 动态三轴 + 上次互动时间 |
| `3w:known-models` | 拉取过的模型名 |
| `3w:ctx-window-overrides` | 用户手动覆盖的上下文上限 |
| `3w:onboarded` | 新手引导是否跑过 |

**导出一份带走**：设置 → 数据留底 → 导出 JSON。

**导入回来**：设置 → 数据留底 → 导入 → 选文件。

选中之后**不会立刻写**，先弹一张对照表：文件来自什么时候、几项有内容、每一项本地有没有。看完再选：

| 选项 | 做什么 | 什么时候用 |
|---|---|---|
| **只补缺失** | 只写本地还空着的项 | 换机器、只丢了某几项 |
| **覆盖本地** | 文件里有的项全部替换本地 | 确定就要这份文件里的内容 |

本地全空时两个选项结果一样，只出现一个「导入」按钮。文件里某项本身是空的（比如某份备份没有 API 凭据），那一项不会出现在列表里 —— 它不会被导入，也不会把本地的清掉。

**清空对话但保留角色**（F12 控制台）：

```js
localStorage.setItem('3w:threads', JSON.stringify({ v: 1, threads: {} }));
```

⚠️ **不要用 `removeItem`** —— 那样下次加载会判定「从没存过」，示例数据会复活。

## 发送、取回、删除

**按 Enter 之后有 6 秒。**

| 操作 | 结果 |
|---|---|
| Enter | 消息上屏（**半透明 0.55 + 倒计时条 + 「待发」**）。**她还没收到。** |
| 6 秒内再 Enter | 立即发出 |
| 6 秒自然走完 | 自动发出 |

### 6 秒内：右键那条消息

| 项 | 提示 | 做什么 |
|---|---|---|
| **取回** | 她还没收到 | 消息消失，**文字回到输入框**，计时器作废 |
| **删除** | 当没发过 | 真的扔掉，连文字都不留 |

**她全程不知道有这条。**

### 发出去之后：没有撤回

**撤回的前提是「对方还没看到」。她回了，就说明她看到了 —— 那就没有可撤回的东西了。**

所以发出之后，右键菜单只有三项：**复制 · 引用 · 朗读**。

**没有撤回，也没有编辑。** 已发出的消息不能改 ——
否则她下一轮会看到自己「回了一句你没说过的话」，要么跟着编，要么出戏。

**这是设定，不是限制：话一旦说出口，就是泼出去的水。**

### 连按 Enter 也不会乱

有 **2 秒最小间隔**，而且**她在回的时候新消息会排队** —— 两条回复的顺序不会颠倒。

## 右键菜单

**消息上没有悬停图标，所有操作都在右键里。**

| 对象 | 菜单项 |
|---|---|
| **她的消息** | 复制 · 引用 · 朗读 |
| **你的 · 已发出** | 复制 · 引用 · 朗读 |
| **你的 · 待发中** | 复制 · 引用 · 朗读 ─── 取回 · 删除 |
| **角色卡** | 编辑角色 · 置顶 · 归档 · 强制改名… · 删除角色 |

### 置顶

右键角色 → **置顶** → 它出现在左栏最上面的「置顶」分组，**不再出现在原来的分组里**。

再右键 → **取消置顶**。

### 归档

右键角色 → **归档** → 从列表消失，底部出现「▸ 已归档 N」。

点开 → 角色回到原来的分组（顺序、颜色、状态全不变）。

**归档不是删除**：对话、记忆、关系全都还在。

## 怎么测

**一律在桌面端测**：

```powershell
npm run desktop:prod     # 构建 + 启动（改了代码用这个）
node scripts/run-electron.mjs --prod   # 只重启（dist 已构建）
```

浏览器预览（`npm run dev`）**不作为验收依据**。两边行为不一样：

| | 浏览器 `127.0.0.1:1420` | 桌面 `app://habitat` |
|---|---|---|
| localStorage | 独立一份 | 独立一份 |
| 文件留底 | 做不到 | 自动 |
| 跨域 API 调用 | 被 CORS 拦 | 主进程代发，不拦 |

**重启前先杀掉旧进程**，否则会占着锁不启动新实例：

```powershell
Get-Process electron -ErrorAction SilentlyContinue | Stop-Process -Force
```

启动后看日志确认三行：

```
[electron] 生产模式协议: app://habitat/
[electron] origin = app://habitat
[electron] localStorage = ok
```

`origin` 不是 `app://habitat` 就说明走的是端口回退，数据会分家 —— 这时别忙着找 bug，先把 1420 端口腾出来。

## 演示参数

URL 后面可以加：

| 参数 | 作用 |
|---|---|
| `?sim=boot` | 完整启动动画 |
| `?sim=boot-fatal` | 启动失败 |
| `?crash=ident` | 指定区块崩溃（12 种：`ident` `api` `freeze` `tomb` `lost` `void` `inputlock` `sealed` `strike` `radar` `sparkline` `tear`） |

同一区块连按两次同 kind 会取消。

桌面端加参数的方式：临时改 `main.cjs` 里的 `win.loadURL("app://habitat/?crash=radar")`。

**生产构建里应该关掉这些。**

## 启动排错

从源码跑的时候会遇到的三个坑。

### 单实例锁：重启前先杀进程

桌面版是单实例的。旧进程没退干净，再启动会静默失败 —— **没有任何提示**。

```powershell
Get-Process Habitat, electron -ErrorAction SilentlyContinue | Stop-Process -Force
```

### `origin` 不对 = 数据会分家

启动日志里这三行是关键。第三行不是 `ok`，或者 `origin` 不是 `app://habitat`，
说明数据写到了另一个源下面 —— 之前的对话会「消失」。

```
[electron] 生产模式协议: app://habitat/
[electron] origin = app://habitat
[electron] localStorage = ok
```

**为什么会分家**：`localStorage` 按 origin 隔离。`app://habitat` 和
`http://localhost:5173` 是两个不同的 origin，各自有一份存储。

### 浏览器预览连不上远程 API

渲染进程有同源策略，直连远程 API 会被 CORS 拦。桌面版由主进程代发，没这个问题。

**所以真正的验收环境是桌面端，不是浏览器。**
