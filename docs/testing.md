## 启动

```powershell
cd D:\Habitat_App
npm run desktop:prod
```

**不用手动杀旧进程** —— 脚本启动前会自己清掉上一次的实例（只清本项目的，不碰别的 Electron 应用）。

启动日志里这三行是关键：

```
[electron] 生产模式协议: app://habitat/
[electron] origin = app://habitat
[electron] localStorage = ok
```

`origin` 不是 `app://habitat` 就说明走了端口回退，数据会分家 —— 那时候别找 bug，先看端口。

## 测 1 · 启动时自动恢复

验证「文件留底能把 localStorage 救回来」。

**做什么**

1. 打开 app，确认左侧有 8 个角色、对话记录都在
2. 关掉窗口（右上角 ×，**不要**用任务管理器强杀）
3. 删掉整个文件夹：

   ```
   %APPDATA%\habitat\Local Storage
   ```

   这一步模拟「清了浏览器缓存 / 换了 origin」

4. 重新 `npm run desktop:prod`

**看什么**

- 启动序列第一行应该写 **`核对本地留底 · 补回 4 项`**
- 角色、对话应该全部回来，一条不少

**什么算通过**

| 现象 | 判定 |
|---|---|
| 第一行「补回 4 项」+ 数据全在 | ✅ 通过 |
| 第一行「补回 0 项」/「本地已最新」+ 数据全在 | ⚠️ 说明 localStorage 没被删干净，重试第 3 步 |
| 第一行「无留底」+ 回到新手引导 | ❌ 恢复没生效，把日志给我 |
| 数据全在但第一行是「补回 N 项（N≠4）」 | ⚠️ 记下 N 是多少，可能是某一项没存 |

## 测 5 · 语音三档

**先测「系统」那一档 —— 零配置**

1. 设置 → 语音 → 点 **「系统」**
2. 音色下拉应该有系统音色（数量因机器而异）
3. 点 **试听**

**什么算通过**

| 现象 | 判定 |
|---|---|
| 听到「你好，我在」 | ✅ **零配置能用，「能听」这一层成立了** |
| 下拉是空的 | ❌ 音色列表要等 `voiceschanged`，等一秒再看；还空就是环境不支持 |
| 点了没声音 | ❌ 先看 Windows 音量混音器里这个 app 是不是被静音了 |

**再测朗读按钮**

1. 跟她聊一句，拿到回复
2. 鼠标移到那条消息上 → 点 🔊
3. 再点一次

| 现象 | 判定 |
|---|---|
| 念出来，再点停 | ✅ 通过 |
| 只弹一个提示不出声 | ❌ **你拿到的是旧版** —— `doSpeak` 曾经是假的 |
| 按钮不变色 | ❌ 拿 `pending`/`speaking` 状态给我看 |

**云端那一档（可选）**

填 Base URL + Key，点试听。常见返回：

| 返回 | 含义 |
|---|---|
| 200 | 通了 |
| **404** | 这个服务商没有 `/v1/audio/speech` |
| **400** | 端点有，参数不对（模型名或 voice） |

> **注意**：不是所有 TTS 服务都兼容 OpenAI 格式。Azure / 阿里 / 腾讯 / 火山要各自签名，用不了。
> 换一家，或者搭个 one-api / new-api 网关转一道。

## 测 6 · 6 秒待发窗口

**做什么**

1. 打一句话，按 Enter
2. **立刻**盯着屏幕看，别动

**看什么**

| 应该看到 | |
|---|---|
| 消息**半透明** | ✅ |
| 上方 **「待发」+ 橙色倒计时条** | ✅ |
| **AI 没有开始回复** | ✅（她还没收到） |

**注意**：真的半透明是 `opacity: 0.55`。如果看起来和不待发的一样，
说明 `motion` 的 `animate` 把 `style` 覆盖了（曾经真发生过）。

**然后分四种走法**

| 走法 | 应该 |
|---|---|
| **右键 → 取回** | 消息消失，**文字回到输入框**，提示「已取回 · 改完再发，她没收到」 |
| **右键 → 删除** | 消息消失，**文字不回输入框**，提示「已删除 · 她没收到过」 |
| **立刻再按一次 Enter** | 消息变正常，她开始回复 |
| **什么都不做** | 6 秒后倒计时收完 → 变正常 → 她开始回复 |

**6 秒之后：没有撤回**

等消息彻底发出（她回了），再右键那条消息 ——

| 现象 | 判定 |
|---|---|
| **只有三项**：复制 · 引用 · 朗读 | ✅ 正确 |
| 还有「撤回」或「编辑」 | ❌ 拿到旧版了 |

> **这是设计不是漏做**：撤回的前提是「对方还没看到」。
> 她回了，就说明她看到了 —— 那就没有可撤回的东西了。
>
> 所以「6 秒后撤回」这条路整个删掉了，`grep "撤回"` → 0 个入口。

**提交闸门**

1. 打第一条 → Enter → 立刻再 Enter（提交）
2. **马上**打第二条 → Enter → 立刻再 Enter
3. 观察两条回复的**顺序**

| 现象 | 判定 |
|---|---|
| 顺序正确、typing 没提前消失 | ✅ 闸门生效 |
| 顺序颠倒 / typing 闪一下就没了 | ❌ 闸门没生效，把 `scheduleReply` 的 `timers.current` 那几行给我看 |

## 测 10 · 落盘

**基础**

1. 说一句话
2. 等 **6 秒**
3. 打开 `%APPDATA%\habitat\data\current.json` 看修改时间

| 现象 | 判定 |
|---|---|
| mtime 是刚才，里面 `3w:memories` 有那条 | ✅ 通过 |
| mtime 没变 | ❌ 定时器没跑，看 `setInterval(tick, 5000)` 那段 |

**连续改动**（这是换掉防抖的原因，必须单独测）

1. 每 1–2 秒发一条，**连发 4–5 条**
2. **手不停**，在第 5 秒左右去看文件
3. 看 `current.json`

| 现象 | 判定 |
|---|---|
| **文件已经写了**（内容是中途的快照） | ✅ 通过 |
| 文件一直没动，等你说完几秒后才写 | ❌ **你拿到的是旧版防抖** |

**记忆手术**

1. 记忆卡上点「铭刻」或「忘掉它」
2. 等 6 秒
3. 看文件的 mtime

| 现象 | 判定 |
|---|---|
| mtime 变了 | ✅ 通过 |
| mtime 没变 | ❌ **记忆变更没进落盘依赖** —— 这是曾经的真 bug |

> **那个 bug 的细节**：`3w:memories` 不在 `[threads, personas, groups, credTick]` 里，
> 所以手术只改 localStorage 不写文件。修法是 `writeAll()` 发 `MEMORY_CHANGED` 事件，
> App 订阅后 bump `memTick`，计数器进依赖数组。

## 一条经验

**改完东西别用任务管理器强杀 app。** Chromium 的 localStorage 是异步落盘的，强杀会丢掉最后几秒的写入。

正常关窗口（×）就行。真遇到卡死必须强杀时，先看一眼 `%APPDATA%\habitat\data\current.json` 的修改时间 —— 只要它是最近的，强杀也没关系，下次启动会从文件恢复。
