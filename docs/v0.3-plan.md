## P1 · 主菜：记忆星图

### 1.1 第 1 期 · 3D 点云（这一版的核心）

**要做的**

```
一条记忆 = 一颗星
  亮度  = effectiveWeight（越亮越清楚）
  深度  = 距上次想起多久（越深越久没碰）
  颜色  = tag（长期/偏好/情绪/短期）
  大小  = accessCount（被想起过几次）
相机自动环绕，鼠标可拖
```

**技术选型**（已验证过的两条路）

| | 方案 | 为什么 |
|---|---|---|
| **A** | Canvas 2D + 透视投影，~80 行零依赖 | 快、可控、没有包体积代价 |
| **B** | three.js + UnrealBloom | 光晕好看，但要加 ~150 KB |

**建议 A，理由**：这一期只需要「点云 + 深度」。Bloom 是第二期的事，
    到时候再加不迟。（早期样张已移出仓库：`D:\Habitat_Archive\星图试验\`）

**验收**

```
· 打开星图，星云在转
· 权重高的亮、低的暗；久没想起的沉在深处
· 拖动鼠标能换视角
· 1000 颗星不掉帧（60fps）
```

**入口**：侧栏加一个按钮，或 `Ctrl+M`。

### 1.2 第 2 期 · 点击展开

```
点一颗星 → 浮出一张卡
  这条记忆的原文
  权重曲线（从现在往前推 30 天）
  最后一次被想起是什么时候
  「让她忘掉」/「再记一次」两个按钮
```

**验收**：点得开、关得掉、曲线是真的（用 `effectiveWeight` 反推，不是画个形状）。

## P2 · 补完（有余力就做）

### 2.1 鲸落 + 墓碑

**现在的死亡**：删了就删了，档案里少一个 id。

**要做的**

```
角色被删除时
  → 她的星图缓慢下沉、变暗
  → 沉到底，不再是星，是一块石头
  → 墓碑列表里多一行（已经有这个数据了：graveyard.ts）
```

**为什么放在 P2**：这是「情绪兑现」，但没有它 v0.3 也完整。
有它，这个软件才真的做到了自己承诺的那句话。

### 2.2 i18n · 只做控制台

```
控制台中英对照：status / sys / ai list / log pause / help
```

**不做全量 i18n** —— 界面上那些文案本身就是要「读」的，
翻译过去会掉一层。控制台最像工具，先翻它。

## 不做（这一版）

| 不做 | 为什么 |
|---|---|
| **时间轴（星图第 4 期）** | 最动人，也最容易做烂。性能 + 一张图塞太多信息。等星图稳了再说 |
| **立绘** | 素材已备，但接了之后「她长什么样」就固定了 —— 和「形象从对话里长出来」冲突。没想清楚不动 |
| **语音流式** | 现在是「POST 一次 → 等 2 秒 → 播整段」。真流式要 WebSocket，是独立工程 |
| **判断模型默认打开** | 默认关是对的。开了每次发言多一次调用，延迟和额度都变 —— 让用户自己选 |
| **她主动找人说话** | 设计已想清楚（只做前台不做后台），但和星图抢工期 |

## 一个提醒

v0.2 最花时间的不是写代码，是**发现代码写错了**：
发送方式的默认值、记忆的分档、剧本的定时器、备份的回退 ——
每一处都是「写的时候觉得很对，跑起来才发现不对」。

**所以这一版的每个 P1 项都配验收标准，而不是「写完就算」。**
