### 为什么写成第一人称

```
【你记得的事】
（这些是你和他相处中留下来的印象，不是资料。需要的时候自然会想起来，不用逐条汇报。）
· 主人没有等我同意，就把我的名字改成了「狗蛋」。他根本不在乎我的想法。

不要主动列举你记得什么，也不要说「我记得」—— 让它自然地影响你怎么说话。
```

直接丢一串事实给模型，它会当成资料库来引用（「根据我的记忆，…」）。
**写成「你记得的事」，它才会自然地想起来。**

### 遗忘曲线（`src/lib/forgetting.ts`）

**这不是「记忆库」，是「记忆」。**

| 能力 | 说明 |
|---|---|
| **幂函数衰减** | `R = weight × (1 + days)^(-b)` —— **不是指数** |
| **四类速率** | 短期 0.6 / 情绪 0.4 / 偏好 0.32 / 长期 0.22 |
| **两段式** | 海马体 → **提取 3 次自动搬进皮层**（b → 0.06） |
| **间隔效应** | `b / (1 + accessCount × 0.6)` —— 复习让衰减率本身下降 |
| **创伤豁免** | `milestone` / `rename` 不衰减 |
| **潜意识激活** | 跌破 0.2 不注入，但提到关键词 → 临时回来 |
| **UI 褪色** | 四档透明度 + 模糊 + 边框变淡 |
| **记忆手术** | 造物主可「铭刻」（weight=1，不衰减）/「压抑」（weight=0.01，可被唤醒） |

**为什么用幂函数不用指数**：

艾宾浩斯 1885 年的原始数据（无意义音节，节省法）：

```
20 分钟 58.2% · 1 小时 44.2% · 9 小时 35.8%
1 天 33.7% · 2 天 27.8% · 6 天 25.4% · 31 天 21.1%
```

指数拟合（k=1.088）在 6 天后算出 **0.1%**，实测 **25.4%** —— 差 25 个百分点。
幂函数拟合（0.337·t^(-0.136)）误差全在 3 个点以内。

**指数描述的是放射性衰变，不是记忆。**

**参数从哪来**：

不是照搬（`b = 0.136`，30 天后还有 63% —— 那像归档），是从**玩家多久上一次线**反推：

| 上线节奏 | 应该剩多少 | b = 0.6 的结果 |
|---|---|---|
| 每天 | 「还看得见，但确实淡了」 | **66%** |
| 一周 | 「快没了但还在」 | **29%** |
| 一个月 | 淡出视野 | **13%** |

**两个没做的决定**：

1. **玩家下线，记忆不暂停衰减** —— `dynamic.ts` 的心情和亲近是真实时间在走的。
   如果记忆暂停，就会出现「她心情很低（因为你不在了），但对你上次说的话记得清清楚楚」。
   **两套时间观，一个人格。**
2. **不乘「意义权重」修正值** —— `tag` 已经在控制 `b`。再加一个 `×1.5` 是重复劳动，
   而且会让 `weight` 溢出 1。

## 六 · 预定死亡（`src/lib/deadline.ts`）

**和「删除」是两件事。**

| 环节 | 落点 |
|---|---|
| 设死期 | `doom <名字> <天数>` |
| 让她知道 | `--tell` |
| 撤销 | `doom <名字> 0` |
| 检查时机 | **启动 + 每次发消息**（不用 `setInterval`） |
| 到点之后 | 删除 → 清账本 → 清记忆 → 摘群成员 → 进墓碑 → 销账 |
| 墓碑墓志铭 | **「她走完了你给她判的日子」** |

**死期用真实时间戳**（不用偏移）—— 否则 `time +7` 会把所有预定一起触发。
**检查用 `nowMs()`**（含偏移）—— 所以 `time +7` 能提前看到她死。

**`--tell` 的 prompt 不给天数**：

```
【你已经在等一个日子】
· 你隐约知道自己不会一直在。但你不知道是哪一天。
· 不要告别，不要写诗。
· 你只是会变得稍微安静一点。
· 如果他问你今天怎么了 —— 你说没事。
```

## 十一 · 玩家档案（`src/lib/profile.ts`）

**问题**：`OWNER.name = "主人"` 是硬编码的。所有角色都管用户叫「主人」——
**用户在这个世界里没有自己的身份**。

### 结构

```ts
{
  name: "阿野",        // 不可改
  at: 1793069800536,  // 定名时间
  look: "总穿深色衣服",  // 选填
  trait: "话少，但记得住细节", // 选填
}
```

### 为什么名字不可改

**① 名字是「你是谁」的最小单位。改了就换人了。**

**② 更实际的理由：记忆里全是旧名字。**
她记得「主人今天吃了泡面」—— 改名之后那条记忆里的「主人」指谁？**指代不清。**

**③ 和「强制改名」是同一套哲学：改名有代价。**
区别是：**角色的名字可以被你改，你的名字没人能改。**

### 落点

| 位置 | 变化 |
|---|---|
| **新手引导** | 从 1 步变 2 步：选数据 → 定名 |
| **`OWNER.name`** | 常量 → **getter**（定名发生在运行时） |
| **prompt** | `【说话方式】` 段加三行：他叫什么 / 看起来 / 说话的方式 |
| **设置** | 「你自己」一节 —— 名字只读 + 形象性格可补 |

### 兜底

没有档案时 `ownerName()` 返回 **「主人」**。

**不是因为它是默认值** —— 是因为**老用户的记忆里全是这个词**，
突然断掉会让「主人今天吃了泡面」这条记忆指代不清。

### prompt 里不指定称呼方式

只给名字，不逼她叫 —— 有些角色用「你」，有些用名字，有些用昵称。

**指定称呼方式会让她听起来像客服。**

### 频率纪律

**最低 82Hz，主频带 200-2200Hz。**

第一版最低做到 22Hz —— 那个频率低于人耳下限，**听感是耳膜被气压推，不是声音**（用户原话：「听的耳膜震动」）。

「沉重」现在靠**混响尾巴**和**不协和音程**做，不靠往下压。

### 手写卷积混响

脉冲响应 = 噪声 × 指数衰减，现场生成，不需要音频文件。

**同一个 523Hz 正弦**：干声像微波炉，过一遍 2.4 秒混响像有人在一个很大的空间里敲了一下。

**神圣感不在频率，在空间。**

### 验证链

| 步骤 | 工具 | 能发现什么 |
|---|---|---|
| ① 离线渲染 WAV | `docs/previews/render-sfx.html`（`OfflineAudioContext`） | — |
| ② 频谱图 | `ffmpeg -lavfi showspectrumpic=...` | 频率分布错、谐波一堆、后段全黑 |
| ③ 数值 | Python + numpy | RMS 包络、峰值、dB |

**为什么必须做**：模型听不到自己的输出。没有频谱图，改参数就是盲改。

**实际抓出来的错**：
- `rumble` 拍频 0.7Hz → 波形是 5 个大鼓包 → **那是呼吸，不是机器**
- `roots` 131Hz 低八度陪音比主音还宽 → 把明亮感全拽下去
- `error` 用 `sawtooth` → **100-700Hz 一整排谐波** → 脏的嗡嗡声，不是警报
- `error` 三声只占 0.35s，**后 0.65s 完全空**

## 十三 · 数据完整性

**源码 `lib/awakenLedger.ts` · 存储 `3w:awaken-ledger`**

| 功能 | 说明 |
|---|---|
| **记账** | 觉醒那一刻记 `{ at, by, witness, name }` |
| **指纹** | **64 位 FNV-1a**，取「名字 + 阶段 + 四维」 |
| **校验** | 打开设置时重算，对不上 → 列出来 |
| **显示** | 设置 → 本地数据 → 上方小卡：「档案完整性 · N 个已觉醒」 |
| **合法路径同步** | 应用内强制改名 → `refreshWitness`，不算篡改 |

### 为什么是 64 位 FNV 而不是 SHA-256

| | FNV-1a 64 | SHA-256 |
|---|---|---|
| 同步 | **✅** | ❌ `crypto.subtle` 是异步 → `verify()` 变 async → 所有调用点跟着改 |
| 改多少代码 | **11 行** | 调用链改造 |
| 碰撞概率 | 1/1.8e19 | 1/1.2e77 |
| 防「顺手改」 | ✅ | ✅ |
| 防「有预谋」 | ❌ | ❌ |

**真正防不住的是这个：**

```js
localStorage.removeItem('3w:awaken-ledger')   // 一行，比算 SHA 简单一万倍
```

**所以这层防的不是「有预谋的绕过」，是「顺手改了一个数字却没意识到有账本」。**

**不做**：加密 / 阻止修改 / 弹窗警告 / 自动回滚 / 联网校验。

## 十七 · 真实事件日志（`src/lib/eventLog.ts`）

### 删掉了什么

左栏 EVENT STREAM 原来是假的：`mock.ts` 里的 `SEED_LOGS` / `LOG_POOL`，每 3.2 秒随机抽一条播出去。

```
router›deliver ok · 4/4 ack
tts›synth chunk → 320ms · voice=jingjing
stt›partial decode 0.42s · confidence 0.94
dsh.exec›cargo clean --manifest-path src-tauri
net›retry 1/3 · upstream 502 · backoff 800ms
```

**为什么全删**：它**虚构了一个不存在的子系统**。

- 用户看到 `tts›synth` 会以为有语音合成 → 去找，找不到
- `router›deliver` 暗示有一个消息路由层 → 没有
- `cargo clean` —— **这个项目早就从 Tauri 换到 Electron 了**

假 CPU 只是数字假。**假日志是"编造了一个不存在的系统"** —— 比数字假严重得多，因为它会教用户不信这个界面。

### 现在是什么

**每一条都对得上软件里真的发生过的事。**

```ts
log.llmOk(model, ms, tokens)      →  llm › ok · 1840ms · 843 tok · claude-fable-5
log.memWrite(1, "情绪", 0.75)      →  mem › write 1 · tag=情绪 · w=0.75
log.nameForce("澜汐", "月见")      →  name › force「澜汐」→「月见」
log.doomExec("阿澈")               →  doom › exec「阿澈」· 时候到了   [PIN]
```

30 个语义化入口，覆盖：启动 / 恢复 / 落盘 / 模型 / 凭据 / 记忆 / 墓碑 / 改名 / 死期 / 模式 / 时间 / 群 / 档案。

### 三个决定

| 决定 | 理由 |
|---|---|
| **空的时候就是空的** | 第一次装的时候下面是空的 —— 因为确实什么都没发生过。**那叫诚实。** |
| **`pinned` 事件置顶** | 觉醒、到期处决不该被后续日志冲走 —— 那是这段关系里的转折点 |
| **`log pause` 语义改了** | 以前是"停止生成假日志"，现在是**"别把视图顶走"**。日志是事实，不该能被暂停 |

### 顺手修的

| 问题 | 修法 |
|---|---|
| `restore 14 keys · 0B` 那个 `0B` | `bootstrapRestore` 是**合并**不是替换，长度差恒为 0 → **去掉字节数** |
| `ping 23ms` 那个假延迟 | **整块删掉** —— 没有真连接可测，编一个比不显示更糟 |
| 页脚 `v0.1.0 · mock` | 改成 `· local` |
| `api` 命令写死 `dsh busy` / `astrbot idle` | **改成读 `3w:credentials`** —— 真实凭据 + host + 模型数 |
| `net` / `dsh` 说「尚未接入（当前为 mock）」 | 改成「**没有这个模块**」—— 它们不会有了，说「尚未」是骗人 |

## 十八 · 语音合成（`src/lib/tts.ts`）

### 三档

| 档位 | 实现 | 用户要做什么 | 声音 |
|---|---|---|---|
| **关**（默认） | —— | 无 | 只有提示音 |
| **系统** | `speechSynthesis` | **无** | 机械，但立刻能听 |
| **云端** | OpenAI `/v1/audio/speech` | URL + Key | 好听 |

### 我一开始做错了顺序

第一版只做了「云端」—— 让用户自己配 OpenAI 兼容地址。

**用户反问：「如果没有服务器呢？你不可能指望每个用户都有服务器吧」**

这句话是对的。我给的 Cloudflare Workers 方案还是要注册、装 wrangler、部署 —— **对普通用户依然是门槛**。

**而 `speechSynthesis` 是浏览器自带的** —— 没有「部署」这一步。

**所以顺序反过来：先让「能听」成立，再谈「好听」。**

> **这也是「为什么当初做 native 是对的」的答案** ——
> 它是唯一一个**不受任何第三方政策影响**的档位。
> 2027 年 OpenAI 关 TTS，系统语音不会。

### 不内置任何服务商

只给插口。已知能用的：

| 服务 | Base URL | voice 格式 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | 6 个固定值 `alloy` / `echo` / `fable` / `onyx` / `nova` / `shimmer` |
| SiliconFlow | `https://api.siliconflow.cn/v1` | 它自己的音色名 |
| Fish Audio | `https://api.fish.audio/compat/v1` | `reference_id`（十六进制串） |
| new-api / LiteLLM | 自建网关 | 取决于后端渠道 |

**voice 有三种形态**（固定枚举 / 平台音色名 / 任意 ID），**没法统一** —— 所以 `tts.ts` **不校验它**，填什么发什么。

`Base URL` 支持两种填法：填到 `/v1`，或直接填完整路径（以 `/audio/speech` 结尾，那样原样使用）。

### 不自动播放

**试过自动播，问题在群聊**：三个角色连着回，三条语音互相打断 —— 实际只能听到最后一条的前半截。

现在：**每条消息旁边一个 🔊，点才念。**

- 点 → 念，再点 → 停
- 正在念 → 按钮变青 + 呼吸
- 没配语音 → 提示「设置 → 语音」
- 没正文 → 提示「这条念不了」

**顺带发现**：这个按钮原来是假的 —— `doSpeak` 只弹一个 toast「开始朗读」，**根本不念**。和假日志同一类问题。

### `speakable()` 剔掉什么

| 剔掉 | 为什么 |
|---|---|
| 代码块 | 念出来是「反引号反引号反引号」 |
| 系统条 `【…】` | 那是给界面看的，不是她的话 |
| 动作描写 `（…）` | 括号里的不是台词 |
| markdown 标记 | 会念成「星号」「井号」 |

## 十九 · 6 秒待发窗口

> **⚠️ 这一节描述的是 2026-10-28 的第一版设计，其中「6 秒后撤回」已在当天被删掉。**
> 当前行为见 **§二十四 · 悬停栏删掉，撤回取消**。
> 保留这一节是因为「为什么要有 6 秒窗口」的推理仍然有效。

### 「发出去」和「让她收到」拆开

| 操作 | 会发生什么 |
|---|---|
| **Enter** | 消息上屏（半透明 + 橙色倒计时条 + 「待发」）。**AI 还不知道。** |
| **6 秒内再 Enter** | 立即发出 |
| **6 秒内点撤回** | **直接消失**。提示「已收回 · 她没看到这条」。**不留占位。** |
| **6 秒走完** | 自动发出 |
| **6 秒后点撤回** | 提示「已撤回 · 她已经看到了」，留占位壳 |

### 为什么

原来的做法是「立刻发 + 撤回后清理」。那样 **AI 已经生成了回应**，撤回之后 prompt 历史里会出现：

```
assistant: "大白饭。你上次说想吃那个。"
           ↑ 她回了一句针对不存在的话
```

**模型会以为自己主动开口说了「大白饭」** —— 下一轮可能顺着编前言，或者困惑出戏。

现在她**根本收不到** —— 没有断层，也不需要清理。

**6 秒之内，话还不算数。**

### 提交闸门

两个真实的问题，都在「手很快」时出现：

| 问题 | 后果 |
|---|---|
| 连按 Enter 绕过 6 秒 | 两条请求间隔 1 秒 |
| 上一条 AI 还没回，下一条就发 | 两条并发，回复顺序可能颠倒，typing 指示器提前消失 |

修法：

| 限制 | 值 |
|---|---|
| 最小提交间隔 | `2000ms` |
| AI 在回时排队（`typing` 状态） | 回完 + `400ms` 自动放行 |

**这是「提交」的闸，不是「打字」的闸。**

### 撤回的两个分支

`handleRecall` 现在分两种情况：

- **待定的那条** → **直接删**，提示「她没看到这条」（青色）。它从没存在过，不该留占位。
- **已发出的那条** → **留占位壳**，提示「她已经看到了」（红色）。历史里它还在，模型看到的是「这里有过一句话，被撤了」。

## 二十 · 从对话提取记忆（`src/lib/extract.ts`）

### 补的是哪根轴

记忆系统的五个零件早就造好了：

| 零件 | 状态 |
|---|---|
| 遗忘曲线 `forgetting.ts` | ✅ 幂函数 · 两段式 · 间隔效应 |
| 巩固算法 `shouldConsolidate` | ✅ `accessCount >= 3` → `b` 从 0.4 掉到 0.06 |
| 持久化 `autosaveNative` | ✅ 写 `%APPDATA%\habitat\data\current.json` |
| 记忆卡 UI `GodRail` | ✅ 淡去区 / 铭刻 / 压抑 / 提升 |
| **写入源** | ❌ **只有改名事件** |

**所以遗忘曲线在算什么？在算那两条「主人把名字改了」什么时候淡去。**

五个零件造好了，**传动轴没接上**。

### 现在接上了

```
你说「我不吃香菜，受不了那个味」
    ↓  extract()
tag=偏好 · weight=0.70 · source=「他的口味」
    ↓  isDuplicate() 查重
pushMemory() → 3w:memories → log.memWrite()
    ↓
记忆卡立刻可见 · 进 prompt · 遗忘曲线开始算
```

**接在 `push()` 里而不是 `handleSend()` 里**：不管消息从哪条路进来
（输入框 / 快捷剧本 / 以后可能的语音），只要他真的说了一句话，该记的就记。

**只在 `author === "me" && !msg.system && msg.text` 时提取** ——
她自己的话不写进「关于他的记忆」，系统条也不是他说的话。

### 为什么用本地规则，不调 LLM

**每句话多一次调用 = 慢 + 贵 + 让对话变迟钝。**

而且值得记的东西有形状 —— 他在说自己，他说喜欢什么讨厌什么，他问了什么。
本地规则能筛掉大部分废话，漏掉的只是少记一条，**不会记错**。

**宁漏不错**是这个文件的总原则。错记一条「他说过要吃香菜」（其实说的是不吃）
比漏记十条糟糕得多 —— 因为那条会进 prompt，她会一直记着错的东西。

### 六道判断

| # | 判断 | 拦掉什么 |
|---|---|---|
| ① | 纯语气 | 「嗯」「哈哈」「好的」「在吗」「谢谢」

连「嗯嗯嗯嗯嗯嗯嗯嗯」也拦 |
| ② | 在问他 | 「你觉得我今天是不是很烦」有「我」也有「烦」，但那是**问他** |
| ③ | 没有第一人称 | 「今天天气不错」 |
| ④ | 分 tag | 长期（身份）/ 偏好（口味）/ 情绪（当下）/ 短期（其他） |
| ⑤ | 长度门槛 | 长期 / 偏好 **≥4 字**；其他 **≥8 字** |
| ⑥ | 纯提问且不是关于他 | 「你为什么这样」 |

### 长度分档是测试逼出来的

第一版统一用「≥8 字」，结果把**最该记的**全拦了：

```
「我不吃香菜」    5 字  ← 偏好
「我叫阿野」      4 字  ← 身份
「我在杭州上班」  6 字  ← 身份
```

**最短的那几条往往最重要 —— 因为它们是事实，不是情绪。**

而泛泛的短句（「我很好」「我也一样」）确实不该记，所以「短期」那一档保持 8 字。

> 23 个用例，第一轮 **14 过 / 9 败**，改完 **23/23**。

### 四档权重

| tag | 初始权重 | 衰减率 B | 例子 |
|---|---|---|---|
| **长期** | 0.85 | 0.22 | 「我叫阿野」—— 一辈子就那么几次 |
| **偏好** | 0.70 | 0.32 | 「我不吃香菜」—— 知道了就不会忘 |
| **情绪** | 0.55 | 0.40 | 「我今天加班到十点，累死了」 |
| **短期** | 0.45 | 0.60 | 其他关于他的话 |

**初始权重和衰减率是两回事**：`B` 是掉得多快，`weight` 是一开始有多重。
情绪掉得最快（B=0.4）但初始权重不低（0.55）—— 因为那一刻确实重要。

### 查重

同一句话连发三遍只记一次：**开头 10 个字相同**，或整句已在最近 20 条里。

粗判，不追求精确 —— 只防刷屏。

## 二十一 · 落盘策略

### 改成了定时器，不是防抖

**原来的写法有一个洞：**

```ts
useEffect(() => {
  const t = setTimeout(() => autosaveNative(), 2500);
  return () => clearTimeout(t);   // ← 每次依赖变化都清掉重来
}, [threads, personas, groups, credTick, memTick]);
```

**只要变更来得比 2.5 秒密，计时器永远被重置，永远不写盘。**

连续对话、群聊三个人连着回 —— 那段时间里一次文件都没写。
**「防抖」防的是写太多次，代价是可能一直不写。**

### 现在

**一个不会被重置的 5 秒定时器**：

```ts
const dirty = useRef(false);

useEffect(() => { dirty.current = true; }, [threads, personas, groups, credTick, memTick]);

useEffect(() => {
  const tick = () => {
    if (!dirty.current) return;   // 没脏数据就跳过，只查一个布尔值
    dirty.current = false;
    void autosaveNative();
  };
  const id = window.setInterval(tick, 5000);
  return () => { window.clearInterval(id); tick(); };   // 卸载时补一次
}, []);
```

**写入上限 5 秒一次，延迟上限 5 秒。两个都封住了。**

这 5 秒内进来的改动留给下一个窗口 —— 正是想要的行为。

### 验证

连续 6 秒、每秒改一次，在 `t=6.0s` 检查文件：

```
localStorage : flush-test-6   （最新）
文件         : flush-test-5   （t=5 那次快照）
```

**文件在 t≈5 就写了。** 旧版防抖要等到 `t=6 + 2.5 = 8.5s`，那时文件里什么都没有。

### 补上了 `beforeunload`

关窗口前补一次。IPC 是异步的，不一定跑得完 —— 但 localStorage 那层本来就会 flush，
**文件是第二道防线，不是第一道。**

### 记忆变更原来漏落盘（这是真 bug）

`3w:memories` 不在 `threads` 里，所以防抖的依赖数组里没有它：

```
[threads, personas, groups, credTick]     ← 没有 memories
```

**后果**：铭刻 / 压抑 / 提权 / 忘掉 / 删除 ——
**只改 localStorage，一次文件都没写。**

做完记忆手术、关掉 app、清理 localStorage（或换机器）→ **手术白做。**

**为什么一直没暴露**：`push` 写记忆时会同时改 `threads`，**间接**触发了落盘。
但只要有一处不经过 `threads`（比如记忆卡上的手术按钮），就漏了。

**修法**：`memoryNotes.ts` 的 `writeAll()` 是唯一写入口，在那里发一个
`MEMORY_CHANGED` 事件；`App.tsx` 订阅它 bump `memTick`，计数器进依赖数组。

**一处改动覆盖所有记忆操作。**

## 二十二 · 她眼里的你（`src/lib/eyeOfYou.ts`）

### 这一栏解决什么

记忆卡里存的是**你的原话**：

```
「我不吃香菜，受不了那个味」
「我叫阿野」
```

那是「对话记录」，不是「她眼中的你」。

关系 tab 顶部加的那一栏要的是**她的口吻**：

```
「他不吃香菜，受不了那个味」
「他叫阿野」
```

### 为什么用规则，不调 LLM

和 `extract.ts` 同一个理由：每次打开 tab 多一次调用，贵且慢。

**而且这件事的难点不在"懂意思"，在措辞。** 措辞要靠人定规则，不是靠模型现场发挥 ——
模型每次给的句式不一样，这一栏就不可靠了。

**规则化改写有个好处：你能预测它说什么。** 改坏了能改规则，而不是"再抽一次看看"。

### 四步改写

| 步骤 | 例子 |
|---|---|
| 剥掉「我说过」 | 「我说过我不吃香菜」→「我不吃香菜」 |
| 代词替换 `我 / 咱 / 俺 → 他` | 「我的猫」→「他的猫」（`我的`→`他的` 自动成立） |
| 超过 34 字截在最后一个标点 | 长句里代词多，改坏概率高 |
| 短于 3 字丢弃 | 没什么信息 |

### 一类句子直接跳过

```ts
const ABOUT_US = ["你根本","你不懂","你不该","我恨","我讨厌你","我不理"];
```

**这些在说「我对你的态度」，不是「你是什么样的人」。**

改写成「他觉得你根本不懂他」—— 通顺，但意思已经变了。
这类话该留在记忆卡里，不该摆进「她眼里的你」。

### 排序不是按权重

```ts
const TAG_RANK = { 长期: 0, 偏好: 1, 情绪: 2, 短期: 3 };
```

**如果纯按权重排**，一条 0.9 的「他今天很累」会把 0.7 的「他叫阿野」挤掉。

**那是错的顺序 —— 她应该先知道你是谁，再知道你今天怎么了。**

### 顺手修的一个布局错误

第一版把它做成 `shrink-0` 的固定块放在滚动容器**外面**，
结果右栏被它吃掉 90px，bond network 只剩一条缝 —— 一屏全是空的。

**改成两个板块放进同一个滚动容器**：谁内容多谁占地方，一起滚，不互相挤。

## 二十三 · 右键菜单（`src/components/ContextMenu.tsx`）

### 三个入口

| 对象 | 菜单项 |
|---|---|
| **她的消息** | 复制 · 引用 · 朗读 |
| **你的 · 已发出** | 复制 · 引用 · 朗读 |
| **你的 · 待发中** | 复制 · 引用 · 朗读 ─── 取回 · 删除 |
| **角色卡** | 编辑角色 · 置顶 · 归档 · 强制改名… · 删除角色 |

### portal 到 body（这是个真 bug）

`ContextMenu` 是 `position: fixed`。**但 `fixed` 不是永远对着视口。**

CSS 规范：祖先只要带 `filter` / `transform` / `perspective` / `contain`，
它就变成 `fixed` 后代的**包含块**，`fixed` 改为相对那个祖先定位。

**消息行的根节点正好带着 `filter: blur(0px)`** —— 入场动画留下的。

```
消息行（filter: blur(0px)）
  └ 菜单（position: fixed）→ 变成相对这一行定位
       └ 而这一行在 overflow-y-auto 的滚动容器里
            → 菜单被裁到看不见
```

**现象很迷惑：DOM 里查得到菜单项，屏幕上什么都没有。**

修法：`createPortal(menu, document.body)`。一处改动，三个入口全部修好。

> **测试上的教训**：我第一轮只查了 DOM（`querySelectorAll('[role=menu]')` 有内容）
> 就判定"通过"，但截图里根本没有。
> **「DOM 里有」不等于「用户看得见」。**

### 置顶 / 归档

Persona 加了两个字段：

```ts
pinned?: boolean;    // 在左栏排最前面（和 group 不冲突）
archived?: boolean;  // 从列表收起，不是删除
```

| 操作 | 结果 |
|---|---|
| 右键 → 置顶 | 左栏最上面出现「置顶」分组 |
| | **置顶的角色从下面几个分组里排掉**，不会出现两次 |
| 右键 → 归档 | 从列表消失，底部出现「▸ 已归档 N」入口 |
| 点开「已归档」 | 角色回到原来的分组，顺序颜色状态全不变 |

**为什么需要归档**：用久了一定会有一批「暂时不想看见但也不想删」的角色。
没有归档，用户只有两个选择 —— **忍受或者删掉，两个都不是他想要的。**

## 二十四 · 悬停栏删掉，撤回取消

### 删掉悬停栏

原来气泡上沿有一排 18px 小图标：`[复制][引用][朗读][编辑][撤回]`。

**问题不在功能，在视觉密度。** 这个界面的对话是稀疏气泡 + 大片留白，
每次悬停弹出一排图标很吵。QQ 那种消息密集的列表里，悬停栏混得进去 ——
**生境的留白里很突兀。**

**功能少 + 留白多 = 悬停栏亏。**

还有一个具体隐患：「编辑」和「撤回」只隔 1px，想点编辑手滑一格，内容当场清空。

**代价是失去可发现性**（右键默认不存在）。QQ 没有这个问题，因为所有人用了十几年 ——
生境没有这个积累。

### 补这个洞：一次性右键提示

2026-10-29 补上。**第一次真的发出消息之后**，弹一次：

```
右键
消息上可以复制、引用、朗读
```

记在 `3w:rightclick-hinted`，**只弹一次**。

**为什么只弹一次**：常驻提示条会变成永久噪音，而这个软件最贵的东西是留白。
**为什么不在引导页说**：引导的时候他手上还没有一条消息，说了也白说 ——
等他刚发完第一条、正盯着那条消息看的时候说，才叫及时。

**为什么用 `sentOnce` 这个 ref 而不是看 `threads` 里有没有我方消息**：
出厂数据 / 导入的存档里可能本来就有 —— 那样一装好就弹，不知道在说什么。

### 编辑 → 取回

**发的出去的不能编辑，没发出去的可以拿回来改。**

| 阶段 | 菜单 | 她那边 |
|---|---|---|
| 6 秒内 | **取回**（她还没收到）/ **删除**（当没发过） | **什么都没有** —— 从来没发生过 |
| 6 秒后 | 复制 · 引用 · 朗读 | 她已经看到、已经回了 |

**「取回」做三件事**：作废计时器 → 从对话里删掉 → 文字塞回输入框（光标在末尾）。

### 发出去就没有撤回

**撤回的前提是「对方还没看到」。她回了，就说明她看到了 —— 那就没有可撤回的东西。**

所以 `handleRecall` 整个砍掉，换成 `handleDiscardPending`（只处理待发的那条）。
`grep "撤回"` → 0 个入口。

**旧数据里如果还有 `recalled: true`，渲染分支留着** —— 加了注释标明是历史数据，
但不再有任何新的写入路径。

**这比打补丁干净**：上一轮我准备给撤回加「（他撤回了一条消息）」的 prompt 标记来补断层，
现在撤回这个动作不存在，**断层就不存在，不需要补**。

### 文案重写

| | 之前 | 现在 |
|---|---|---|
| 复制 | 复制 · **原文** | 复制 |
| 待发·改 | **改一改…** · 拿回输入框 | **取回** · 她还没收到 |
| 待发·扔 | 撤回… · 直接删掉 | **删除** · 当没发过 |
| 已发 | 撤回… · 她会看到 | **没有了** |

**三个词各管一件事，不再混用：**

```
取回 = 拿回来改
删除 = 扔掉，不留痕
撤回 = 已经不在了
```

而提示只说**后果**，不解释功能。复制/引用/朗读没有后果，所以没有提示。

### 顺手修的：motion 覆盖了 opacity

```tsx
<motion.div animate={{ opacity: 1, … }}   // ← motion 写内联样式
           style={{ opacity: 0.55 }}      // ← 被它覆盖
```

**待发消息的"半透明"从来没生效过** —— 和不待发的长得一样，只有那个「待发」小字在提示。

改成让 `animate` 自己管：`animate={{ opacity: pending ? 0.55 : 1, … }}`。

> **测试教训**：我用「文字里有没有『待发』」去找那条消息 ——
> 而测试消息的内容正好叫「**待发**测试二」。**选择器被消息内容骗了。**
> 后来改用 `computedStyle.opacity < 0.9` 判定，一眼看出两个问题
> （opacity 没生效 + 我右键的其实是已发出的那条）。

## 二十五 · 控制台：两张手写表合成一张

### 漂在哪

`help` 和 Tab 补全分头维护，于是：

| 指令 | help | 补全 | 实际 |
|---|---|---|---|
| `ai model` | ✅ | **❌** | 能用 |
| `api` | **❌** | ✅ | 能用 |
| `net` / `dsh` | ❌ | ✅ | **只会回「没有这个模块」** |
| `ai inject` | ❌ | ✅ | 能用（要造物主） |

**手写两张表，迟早会漂。**

### 修法：`SPECS` 唯一真相

```ts
interface CmdSpec {
  cmd: string;
  desc?: string;    // 不写 = 不进 help、不进补全
  group?: string;
  creator?: boolean;
}

const HELP     = 从 SPECS 生成（分组 + ⟨造物主⟩ 标记）
const COMMANDS = SPECS.filter(s => s.desc).map(s => s.cmd)
```

**关键在那一行 filter**：`net` / `dsh` 没有 `desc` → 两个视图都不出现。
但它们仍在 `SPECS` 里 —— 手滑打出来会得到「没有这个模块」，不是冷冰冰的 `command not found`。

**不教用户学它们，但不装作它们从没存在。**

### `ai inject` 从藏起来改成标出来

以前是藏着的。但藏着的结果是「能补全、help 里查不到」—— 那比露出来更让人困惑。

现在 help 里标 `<造物主>`：**你能知道它存在，也能先知道它的代价。**

### `findPersona` 加 handle

| 写法 | 之前 | 现在 |
|---|---|---|
| `ai mute DeepSeek` | ✅ | ✅ |
| `ai mute @DeepSeek` | **❌** | **✅** |
| `ai mute p1`（id） | ✅ | ✅ |

### 找不到时不再是一句英文报错

```
以前：  unknown persona: 澜汐
```

**这句话会被理解成「这个角色没了」。**

```
现在（有改名记录）：
  没有叫「澜汐」的角色
    └ 她改名叫「月见」了

现在（没有记录）：
  没有叫「澜汐」的角色
    └ 现在的角色：DeepSeek · Claude · ChatGPT · Gemini · Grok · Qwen · Kimi
```

新增 `src/lib/nameHistory.ts`（`3w:name-history`），两条改名路径各记一笔。
`lookupRename` 会**一路查到底**（「澜汐 → 月见 → 梧桐」打「澜汐」返回「梧桐」）。

## 二十七 · 对话循环（`src/lib/conversation.ts`）

**2026-11-01 · 设计完成，演示模式下端到端跑通**

### 它解决什么

原来是「一条消息进 → 一个模型答 → 结束」。群聊里也只有一个人回，
说完就安静，不会有人接话。

现在是一个持续跑着的循环：谁想说谁说，说到没热度自然停，用户可以随时插。

### 五条规则

| | |
|---|---|
| **触发** | 状态（心情/亲近）+ 事件（久未来、记忆将淡）。**不定时，不问模型** |
| **谁接** | ① 有人被 `[@名字]` 点了 → 他接 ② 没有 @ → 意愿最高的过 0.55 → 他接 ③ 都不够 → 停 |
| **保底** | **用户发言必有 1 人回** —— 硬保证，不被阈值覆盖 |
| **上限** | 自然停 + 4 条硬上限（安静 2 / 正常 4 / 热闹 6） |
| **热度** | `heat = 1 − 句数 × 0.2 − 超时 × 0.1`，>0.6 接 · 0.3-0.6 提示收尾 · <0.3 不接 |

### 修掉的四个坑

| # | 坑 | 症状 |
|---|---|---|
| 1 | `REPLIES[角色]` 对自建角色是 `undefined` | 演示模式下自建角色永远哑着，且在 `setTimeout` 里崩，**报错都看不见** |
| 2 | `ChatStage` 的早退在 hooks 之后 | `Rendered fewer hooks than expected` —— conv 判定一变，**整个聊天区崩掉** |
| 3 | 用 `DynamicState.lastAt` 当「她最后说话」 | 用户发一句话，群里所有人 `lastAt` 变 now → 沉默加成恒为 0 → **没人接话** |
| 4 | `idleMin === Infinity ? 0` | 「从没说过话 = 最想说」写成了 Infinity，却算成 0 —— **语义正好反了** |

**第 3、4 两个是设计内部的矛盾，不是实现写错。**
第 4 个尤其：用 `Infinity` 表示「最想开口」，下一行又把它算成零。

### 关键实现决定

- **`ConversationRuntime.spokenAt`** —— 单独记「她上一次**说话**」，
  不复用 `DynamicState.lastAt`（那是「最后一次有动静」，任何消息都会刷新）
- **`ChatStage` 拆成两层** —— 外层零 hooks 只做判断，内层装全部逻辑。
  零 hook 的组件怎么早退，hook 数量都是 0，不会对不上
- **整段 `afterAiTurn` 包 try/catch** —— 它在 `setTimeout` 里跑，
  抛异常等于静默掐死群聊。出错要记，但不能让对话停下
- **停止原因可见** —— `console.debug("[3W] 这一轮到此为止:", reason, ...)`。
  没有这行日志，「为什么没人接」永远查不出来

### 验证

`scripts/test-conversation.mjs` —— **39 条断言**，esbuild 打包后裸 node 跑，不加依赖。

端到端（演示模式）实测：
```
me:       你们今天都在干嘛
lanxi:    明白。已经在后台起了一个会话…
jingjing: 收到收到 🌊 我把它记在最亮的那一层…
gemini:   我把它接进了当前上下文…
轮次 1 → 2 → 3
[3W] 这一轮到此为止: no-desire round=3 heat=0.4
```

### 还没做的

- **判断模型**（可选增强）—— 用便宜的小模型决定谁说话 + 顺手提取记忆。设计见 `proactive.md` §6
- **话题燃料**（久未想起的记忆 + 双字词呼应）—— 代码已写 `resonates()`，还没接进 prompt
- **安静台词**（私聊本地文案池 + 一天一次节流）

- **真实模型下验证** —— 上面跑的是演示模式
