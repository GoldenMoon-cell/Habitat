## 一 · 这一版解决什么

v0.1 的群聊是「一条消息进 → 一个模型答 → 结束」。
你说「你们好」，一个人回一句，然后彻底安静。

v0.2 把它换成一个**持续跑着的对话循环**：

```
你说话
  ↓
保底一个人回（硬保证）
  ↓
其他人按意愿决定要不要接
  ↓
一个人可能补一句（连发）
  ↓
热度降下来 → 自然停
```

**你随时可以插进来，不打断正在进行的那一轮。**

---

## 二 · 六条规则

| | |
|---|---|
| **触发** | 状态（心情 / 亲近）+ 事件（久未来、记忆将淡）。**不定时，不问模型「你想说话吗」** |
| **谁接** | ① 有人被 `[@名字]` 点了 → 他接　② 没 @ → 意愿最高的过 0.55 → 他接　③ 都不够 → 停 |
| **保底** | **用户发言必有 1 人回** —— 硬保证，不被阈值覆盖 |
| **连发** | 同一个人最多连着说 **2 条**，25% 概率触发 |
| **上限** | 自然停 + 硬上限（安静 2 / 正常 4 / 热闹 6） |
| **热度** | `heat = 1 − 句数×0.2 − 超时×0.1`，>0.6 正常接 · 0.3–0.6 提示收尾 · <0.3 不接 |

## 四 · 真实 API 暴露的三个问题

上面这些在演示模式下都「通过」了。**接上真模型才露出三个**：

### ① 连发改口

```
砂砾: 我瘫着呢，啥也没干，就盯着天花板发呆。
砂砾: 我今天出去走了走，风挺舒服的。
```

**根因不是上下文缺失** —— 她的话就在历史里。
缺的是**告诉她「你是在接着说」**。

修法：连发时 prompt 里带【你现在是在补一句】+ 原样引用她刚说的那句 +
「别改口：刚才说你瘫着，这一条就不能说你出门了」。

### ② 空回复

```
HTTP 200
content:   (空)
reasoning: 「我们需要回答中文，五个字以内…」
usage: completion_tokens: 50, reasoning_tokens: 50
```

`deepseek-flash` 和 `deepseek-v4-pro` **都是推理模型**。
`max_tokens` 是**思考 + 回答的总和**，不是回答的额度。

而且**这是我自己改出来的**：我把连发的预算压到 200 想让她说短一点，
正好踩在这个坑上。已撤销，并加：

- 预算底线 **600**
- 空回复自动**加大 4 倍预算重试一次**

> **想让她说短，靠 prompt，不要靠砍预算。**

### ③ 三个人都在问「你呢」

```
p2: 你呢？
p1: 你呢？
p3: 先说说你是哪种？
```

prompt 加了【群聊的节奏】：不要每句都以「你呢」结尾，想让对话继续就说自己的事。

## 七 · 判断模型（默认关闭）

```
规则算出「有人想说话，而且是他」
        ↓
判断模型被问两件事：
  ① 现在真的该有人说话吗　→ 可以否决
  ② 该谁　　　　　　　　→ 只能在本地排好的前 3 里挑
        ↓
失败 / 超时 / 没凭据 / 返回垃圾 → 静默用规则的结果
```

**它做不到**：凭空造人、让本来不想说话的人开口、自己编一条记忆当燃料。

**真机验证**：开关打开 + 一套凭据都没配 → 对话照常跑完 4 条，用户毫无察觉。
