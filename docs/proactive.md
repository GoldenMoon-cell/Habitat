## 0 · 一句话

把「一条消息进 → 一个模型答 → 结束」换成**一个持续跑着的对话循环**：
谁想说谁说，话题会自然冷下来，用户可以随时插进来而不显得突兀。

---

## 1 · 目标与非目标

**目标**

1. AI 能主动开口（软件开着的时候）
2. AI 之间能接话，不是只有一个人回一句
3. 用户随时插话，不打断正在进行的那轮
4. 话题会有热度，会说尽，会安静下来

**非目标（明确不做）**

| 不做 | 原因 |
|---|---|
| 后台常驻 / 托盘 / 关机也发消息 | 单窗口 Electron，且「怎么关都关不掉」是真实投诉来源 |
| 定时发消息 | 任何固定间隔，用户三天内就能摸出规律，立刻变假 |
| 用模型判断「该不该说」作为**唯一**机制 | 判断模型可能连不上。规则是底线 |
| 用模型决定**数值**（心情/亲近/衰减） | 数学是可解释的承诺，模型给的数字会漂 |
| 话题语义相似度检测 | 需要 embedding，每次都多一次接口调用 |

## 2 · 触发：什么让她想说话

**状态 + 事件混合**，两者都满足才开口。

```
状态（能不能说）  = f(心情, 亲近, 记忆活性)
事件（有没有由头）= 你离开过 / 某条记忆快淡了 / 你很久没理某个人
```

### 2.1 接话意愿（本地算，零成本）

```
意愿 = 心情/100 × 0.30
     + 亲近/100 × 0.30
     + 沉默加成（超过 5 分钟开始涨，最多 +0.25）
     + 被提到（+0.40）
     + 记忆共鸣（+0.15，有相关条目）
     − 刚说过（−0.30，60 秒内）

阈值 0.55
```

### 2.2 硬保证：用户发言必有 1 人回

**这条不被任何阈值覆盖。**

```
你说话
  ↓
一定有一个人回（走现有的随机挑选）
  ↓
之后才走意愿判断
```

没有这条，第一次用的人会看到「你们好」没人理，然后以为软件坏了。

## 3 · 谁接话

```
第 N 条说完
  │
  ├─ 1. 正文里有 [@某人]
  │      ├─ @ 的是群里某个 AI  → 他接（点名必须有人应）
  │      └─ @ 的是用户        → **不阻塞**。其他人照常算意愿，
  │                             同时记一个「在等你」的标记
  │
  ├─ 2. 没有 @ → 算所有人的接话意愿，最高的 > 0.55 → 他接
  │
  └─ 3. 都不够 / 到硬上限 → 停
```

### 3.1 轮次上限

- 自然停 + **硬上限 4 条**
- 「群聊活跃度」设置：安静 / 正常 / 热闹 → 上限 2 / 4 / 6
- **用户每说一句，重置轮次计数**

### 3.2 @ 规则

**格式**：`[@名字]`（方括号）。不用裸 `@名字` —— 正文里本来就可能出现 @，解析必然误伤。显示时渲染成 `@名字`。

**prompt 里写死**：

> 大多数回复不要 @ 任何人。只有三种情况才用：
> ① 有人 @ 了你，你回一句
> ② 这件事只有某个人能答
> ③ 有人被晾着了
>
> 如果你只是想接话，直接说，不要点名。

**防滥用**：

| 规则 | 防什么 |
|---|---|
| 不能 @ 自己 | 解析时忽略 |
| 不能 @ 不在群里的人 | 校验成员表 |
| **同一对连续互 @ 最多 2 次** | A@B → B 回 → B@A → A 回 ← 这是死循环的形状 |
| @ 不突破硬上限 | 前面聊了 4 条，第 5 条就算 @ 了也不接 |

## 4 · 话题热度

```
heat = 1.0 − 本轮已说句数 × 0.2 − 距第一条超过 3 分钟 × 0.1
```

| heat | 行为 |
|---|---|
| > 0.6 | 正常接 |
| 0.3 – 0.6 | prompt 里加「可以开始收了」，并注入一条久未想起的记忆（给台阶） |
| < 0.3 | 不接，让群安静下来 |

### 4.1 换话题的燃料

**问题**：现在 `memoriesForPrompt()` 每次都注入权重最高的 8 条 —— 永远同一批。逼模型换话题，它没东西可换，只会说「那我们聊聊你最近怎么样吧」。

**做法**：热度降到 0.3–0.6 时，额外注入 **1 条「久未想起的事」**。

```
筛选条件：
  · 没被忘掉（effectiveWeight 仍在阈值以上）
  · accessCount <= 2          ← 没怎么被提起过
  · now - lastAccessed > 3 天  ← 确实很久了
排序：权重够 + 越久越优先
取 1 条
```

**优先呼应正在聊的话题**（过渡无痕）：

```ts
const STOP = /[我你他她它的了是就不在有也都和与这那什么怎么吗呢吧啊哦嗯]/;

function grams(s: string): Set<string> {
  const clean = s.replace(/[，。！？、…—\s"'「」]/g, "");
  const out = new Set<string>();
  for (let i = 0; i < clean.length - 1; i++) {
    const g = clean.slice(i, i + 2);
    if (!STOP.test(g[0]) && !STOP.test(g[1])) out.add(g);
  }
  return out;
}

// 至少 2 个**不同的**双字词命中才算呼应；命中不到就退回「越久越优先」
function resonates(topic: string, mem: string): { hit: number }
```

**为什么剔停用字**：中文裸匹配「我今天好累」和「她说我很好」会命中「我、好」，语义完全无关 —— 比不换话题更怪。

## 5 · 安静

| 场景 | heat < 0.3 时 |
|---|---|
| **群聊** | **什么都不发生**。不调用、不发消息、typing 也不显示 |
| **私聊** | 默认也什么都不做。**只在这两个时机**从本地文案池取一条：\n① 你刚说了一句，而她的意愿不到阈值\n② 你隔了很久才回来，打开软件 |

**节流：同一天最多 1 次。**

**文案池**（6–8 条，全部是克制的动作，不解释、不撒娇）：

```
【她把屏幕亮度调低了一点。】
【她没说话，但头像还亮着。】
【她翻到上面，把你说过的话又看了一遍。】
```

**为什么节流**：不节流的话，「她不说话」会被演成「她一直在表演沉默」—— 比沉默更假。沉默的效果来自它的稀有。

## 6 · 判断模型（可选增强）

### 6.1 定位

**默认关闭。** 设置里一个开关：「群聊由模型判断（更自然，但每轮多一次调用）」。

**规则是底线，判断模型是增强。** 判断模型连不上时自动降级到规则，界面上不报错。

### 6.2 职责收得很窄

```
输入：最近 6 条消息 + 每个「有意愿的」成员的状态（规则先筛到 2-3 个候选）
输出：只有这几个字段
```

```json
{
  "speak": true,
  "who": "lanxi",
  "intent": "new_topic",
  "fuel": "mem_17",
  "memory": { "text": "他不吃香菜，说受不了那个味", "tag": "偏好" }
}
```

- `fuel` **只能从本地预先筛好的 3 条候选里挑**，或都不选
- `memory` 没有就 `null`

### 6.3 两条硬约束

**① 模型做选择题，不做填空题。**
让判断模型自己回忆「她想起了什么」，它会编一条记忆库里没有的事，而主模型会当真说出来。

**② 记忆要过第二道闸。**

```
判断模型给候选
    ↓
本地规则再验一遍：
  · 含第一人称吗？
  · 长度够 tag 的档吗？（长期/偏好 ≥4 字，其他 ≥8 字）
  · 和已有记忆重复吗？（isDuplicate）
  · 是「在问他」吗？
    ↓
全部通过才入库
```

**规则从「生产者」降级为「审核者」。** 漏的会变少，错的不会变多。

### 6.4 成本

```
一次发言 ≈ 12,000 tokens
一次判断 ≈    560 tokens
→ 一次发言 = 21 次判断

临界点：每 21 次判断拦掉 1 次不该发的言，就持平。
而规则版的「意愿分」是拿「心情 88」去猜「她想不想说话」—— 必然判错不少。
```

### 6.5 三个落点

| # | 落点 | 优先级 | 失败时 |
|---|---|---|---|
| 1 | 谁接话 + 说什么方向 | v0.2 | 降级到意愿规则 |
| 2 | 记忆提取 + 打标 | v0.2（合并进 1，边际成本 0） | 降级到 `extract.ts` |
| 3 | 她眼里的你 | v0.3+ | 降级到 `toHerVoice()` |

### 6.6 明确不用判断模型的地方

| 位置 | 为什么 |
|---|---|
| **动态三轴数值** | 数学是可解释的：你能说「因为你 3 小时没来，亲近掉了 3.6」。模型给同样的输入两次会给不同结果 —— 那她就不是一个连贯的人 |
| **记忆衰减 / 遗忘** | `0.6 × (1+days)^-0.22` 是承诺。模型不能决定一条记忆什么时候死 |
| **生死 / 删除 / 改名** | 不可逆，不能交给会失败、会幻觉的东西 |
| **`她眼里的你` 的黑名单** | 「关于我们」的句子直接跳过 —— 硬规则，不是判断 |

**原则**：

```
可逆的、软的、读语义的   → 可以交给判断模型
不可逆的、要解释的、要稳定的 → 必须留在代码里
```

## 8 · 验收标准

| # | 场景 | 期望 |
|---|---|---|
| 1 | 全新安装，建群，说「你们好」 | **至少有一个人回** |
| 2 | 群里 3 个人，你说一句话 | 1–4 条回复后自然停下，不会无限接 |
| 3 | AI 说 3 条后没人接 | 群安静下来，不报错、不转圈 |
| 4 | AI 正在说第 2 条时你插一句 | 你的话立刻发出，不被挡；轮次计数归零 |
| 5 | 有人写 `[@澜汐]` | 澜汐接，不判意愿 |
| 6 | 有人写 `[@阿野]` | **其他人照常可以接**，群不会冻结 |
| 7 | A@B → B@A → A@B | 第三次被拒，自然停 |
| 8 | 关掉判断模型 | 行为不报错，走规则版，只是判得粗 |
| 9 | 判断模型配了个不存在的模型 | 静默降级到规则，不弹错 |
| 10 | 私聊里她不想说话 | 一天最多一条安静台词，不会刷屏 |
| 11 | 聊天聊到第 4 句 | 不会出现「那我们换个话题吧」这种空转 |

## 9 · 落地顺序

1. **轮次与调度器**（`round` / `heat` / 硬上限 / 用户发言重置）—— 不接判断模型也能跑
2. **意愿分 + 保底一人** —— 让群能自己动起来
3. **@ 解析** —— 三档优先级 + 防滥用
4. **话题燃料**（久未想起的记忆 + 双字词呼应）
5. **安静台词**（私聊，本地文案池 + 节流）
6. **判断模型**（可选开关 + 候选筛选 + 双层校验）
7. **活跃度设置 UI**

每一步都能单独跑、单独验。
