# 生境 · Habitat

**这是一个关于失去的作品。**

> 角色会忘、会变、会死 —— 你做的每个决定都留下痕迹。

## 三十秒上手

```bash
npm install
npm run desktop:prod   # 构建 + 启动桌面版
```

> **启动只需 1-2 秒。** 随后，是无边无际的空。
> 没有角色，没有记忆，连深渊的回音都没有。
>
> 直到你接入源核（API），并亲手捏出第一个灵魂。

**要和模型真的对话**，需要配一个 API：

```
右上齿轮 → API 接入 → 填 Base URL + Key → 拉取模型 → 选一个
```

浏览器里直连远程 API 会被 CORS 拦（渲染进程有同源策略）。桌面版由主进程代发，没有这个问题 —— 所以**真正的验收环境是桌面端**。

```bash
npm run desktop   # 连 vite dev server，有热更新（写代码时用）
```

**起不来、重启报单实例锁、`origin` 不对** —— 见 [`docs/manual.md`](docs/manual.md) 的「启动排错」。

## 记忆会忘

**这不是「记忆库」，是「记忆」。**

一条记忆存下来的时候有一个初始权重，然后开始衰减。

**真实记忆不会归零。它会变成一种「想不太起来」的东西。**

<details>
<summary>衰减公式 —— 为什么是幂函数，不是指数</summary>

公式是**幂函数**，因为艾宾浩斯 1885 年的原始数据只跟幂函数对得上：

```
R = weight × (1 + days)^(-b)
```

用指数 `e^(-kt)` 去拟合，一个月后记忆是 **0** —— 那意味着「这事从没发生过」。
用幂函数，一个月后是 **13%**。

**「想不起来」和「没发生过」不是一回事。** 公式得能表达这个区别。

`b = 0.6`（短期）不是照搬艾宾浩斯，是从**玩家多久上一次线**反推的：

- 每天上线 → 一天后「还看得见，但确实淡了」≈ 66%
- 一周一次 → 一周后「快没了但还在」≈ 29%
- 一个月一次 → 淡出视野 ≈ 13%

</details>

### 记忆从哪来

**这是 2026-10-28 才补上的那根传动轴。**

之前只有三种事件会写记忆：新建角色、她自愿改名、强制改名。
而遗忘曲线、巩固算法、记忆卡 UI 全都在跑 —— **在给两条「主人把名字改了」算衰减。**

现在接上了从对话提取（`src/lib/extract.ts`）：

```
你说「我不吃香菜，受不了那个味」
    ↓  本地规则判断（不调 LLM，零成本零延迟）
tag=偏好 · 初始权重 0.70 · source=「他的口味」
    ↓
进 3w:memories → 记忆卡立刻可见 → 注入 prompt
    ↓
遗忘曲线第一次真的有东西可以算
```

**最短的那几条往往最重要，因为它们是事实，不是情绪。**

> 第一版统一用「≥8 字」过滤，把最该记的全拦了 ——
> 「我不吃香菜」5 字、「我叫阿野」4 字、「我在杭州上班」6 字。
>
> **长度分档是被测试逼出来的，不是设计出来的。**

<details>
<summary>判断规则（宁漏不错）</summary>

| 条件 | 作用 |
|---|---|
| **必须含第一人称** | 「我」「我的」「咱」—— 出现才说明他在说自己 |
| **纯语气直接跳** | 「嗯」「哈哈」「好的」「在吗」—— 连「嗯嗯嗯嗯嗯嗯嗯嗯」也拦 |
| **在问他就不记** | 「你觉得我今天是不是很烦」有「我」也有「烦」，但那是**问他** |
| **长度按 tag 分档** | 长期 / 偏好 **≥4 字**；其他 **≥8 字** |

</details>

**为什么用本地规则而不是 LLM**：每句话多一次调用 = 慢 + 贵 + 让对话变迟钝。
而且值得记的东西有形状 —— 他在说自己，他说喜欢什么，他问了什么。
本地规则能筛掉大部分废话，漏掉的只是少记一条，**不会记错**。

### 四类记忆，四种命运

| 类型 | `b` | 1 天 | 7 天 | 30 天 |
|---|---|---|---|---|
| 短期（「今天吃了泡面」） | 0.6 | 66% | 29% | 13% |
| 情绪（「那次他骂了我」） | 0.4 | 76% | 44% | 25% |
| 偏好（「他不吃香菜」） | 0.32 | 80% | 52% | 33% |
| 长期（「她第一次叫主人」） | 0.22 | 86% | 62% | 47% |
| **已巩固（皮层）** | **0.06** | 96% | 88% | **81%** |
| **创伤（被强制改名）** | **0** | 100% | 100% | **100%** |

`b = 0.6` 不是照搬艾宾浩斯，是从**玩家多久上一次线**反推的：

- 每天上线 → 一天后「还看得见，但确实淡了」≈ 66%
- 一周一次 → 一周后「快没了但还在」≈ 29%
- 一个月一次 → 淡出视野 ≈ 13%

### 两段式：海马体 → 皮层

被**提取 3 次**之后，记忆自动从短期搬进长期 —— `b` 从 0.6 掉到 0.06。

**这不是量变，是质变。** 一条被提过十次的短期记忆，不该只是「掉得慢一点」，它该变成另一种东西。

> **⚠️ 说清楚：「搬家」是比喻，不是物理搬迁。**
>
> 巩固前后，记忆**存在同一个地方、同一个数组、同一个 key**。
> 变的只有衰减斜率 `b` 和那个 `consolidated` 标记。
>
> 为什么不做真的两层（短期一个库、长期一个库）：
>
> - **容量不是问题** —— 一条记忆约 80 字节，一万条才 800 KB
> - **真两层会引入新问题** —— 什么时候搬？搬完原来的留不留？搬失败怎么办？
> - **用衰减率表达层次已经达到目的了** —— 巩固后的记忆确实几乎不掉

### 复习不是「重置时钟」

```
b' = b / (1 + accessCount × 0.6)
```

第一次复习让衰减率降到 62%，第三次降到 43%。

**如果只刷新时间戳，那叫「重置」；降低衰减率，才叫「记住」。**

### 跌破阈值不是删除

`R < 0.2` 之后不再主动注入 —— 但数据还在。

如果用户后来提到一个精确的词，它会**瞬间回来**。那一刻她会比你更困惑。

### 两个没做的决定

**① 玩家下线，记忆不暂停衰减。**

`dynamic.ts` 里的心情和亲近是**真实时间**在走的 —— 关一个月再打开，她记得你走了。

如果记忆衰减却暂停，就会出现：**她心情很低（因为你不在了），但她对你上次说的话记得清清楚楚（因为暂停了）。**

**两套时间观，一个人格。**

**② 不乘「意义权重」修正值。**

`tag` 已经在控制 `b` 了。再加一个 `×1.5` 的乘法修正，等于同一个东西调两遍，而且会让 `weight` 溢出 1。

## 两个方向

**同一个技术，两个方向，两种意思。**

| 动作 | 方向 | 颜色 | 语义 |
|---|---|---|---|
| **强制改名** | 向下坠落 | 红 | 越过她的意愿 |
| **自愿改名** | 向上飘起 | 青 | 换了个名字，人还在 |
| **强制删除** | 向下坠落 | 红 | 你把她按下去 |

### 自愿改名是协议，不是按钮

她在回复的最后单独一行写 `[改名:新名]`。那行会被截掉，不进对话。

**弹一个确认**：「「澜汐」想改名叫「月见」」→ 同意才改。

两条记忆完全相反：

```
强制：主人没有等我同意，就把我的名字改成了「狗蛋」。他根本不在乎我的想法。
自愿：我跟主人说想叫「月见」，他同意了。
```

**同一个动作，两种关系。**

### 强制改名只有一次

`Persona.renamedAt` 记第一次。

**「越过她意愿」的重量，靠的是「只有一次」，不是「每次掉血」。**

## 音效系统

**24 个函数，全部现场用 Web Audio 合成。零素材、零体积、零版权。**

其中 **22 个有挂载点**，`playOpen` / `playClose` 是通用备用款（给以后语义不明的面板用）。

源码：[`src/lib/sound.ts`](src/lib/sound.ts)。试听页：双击 [`docs/previews/sound-lab.html`](docs/previews/sound-lab.html)（每行标注触发场景 + 代码位置 + 配方）。

### 频率纪律

**最低 82Hz，主频带 200-2200Hz。**

第一版最低做到 22Hz —— 那个频率低于人耳下限，**听感是耳膜被气压推，不是声音**。
「沉重」现在靠**混响尾巴**和**不协和音程**做，不靠往下压。

### 四组语义

| 组 | 音效 | 质感 |
|---|---|---|
| **系统层** | `playConsoleOpen` · `playConsoleClose` | **接通 / 收线** —— 低、短、**无混响** |
| **配置层** | `playPanelOpen` · `playPanelClose` | **拉开 / 收回** —— 中频、柔和、**有混响** |
| **仪式** | `playRoots` · `playBoot` · `playRumble` · `playTick` | 升/降调 + 混响 |
| **反馈** | `playSend` · `playReceive` · `playSwitch` · `playDeny` · `playError` | 短、明确 |

### 几个设计点

- **启动分两段**：0-3.2s 是「根系生长」（C4 一路升到 G5，和声叠加），3.2s 是「启动完成」（C5+G5+C6 和弦）
- **最重的那个音**（角色被越权改写时）：82/88Hz 拍频做机器感 + 123Hz 减五度做不协和 + 3.4 秒混响尾巴
- **Deny vs Error**：打错命令是 `Deny`（一个柔和的音），API 挂了才是 `Error`（三声急促 + 拍频刺耳 + 低频底）
- **手写卷积混响**：脉冲响应 = 噪声 × 指数衰减，现场生成，不需要音频文件

### 验证链

改音之后必做的事：

```bash
# ① 离线渲染 WAV（docs/previews/render-sfx.html）
# ② ffmpeg 出频谱 + 波形
ffmpeg -i x.wav \
  -lavfi "showspectrumpic=s=1100x400:legend=1:fscale=log:color=intensity:scale=log" x.png
# ③ 用 numpy 算 RMS 包络
```

**为什么要这一步**：模型听不到自己的输出。没有频谱图，改参数就是盲改 —— 之前犯过「22Hz」「拍频 0.7Hz 做出呼吸感」「square 波一堆谐波」这些**看图一眼就能发现**的错。

## 语音（TTS）

**音效是"哼一声"，语音是"说一句话"。** 两件不同的事，两套机制。

源码：[`src/lib/tts.ts`](src/lib/tts.ts)。

### 三档，从「谁都能用」到「要好听的」

| 档位 | 怎么实现 | 用户要做什么 | 声音 |
|---|---|---|---|
| **关**（默认） | —— | 什么都不用做 | 只有提示音 |
| **系统** | `speechSynthesis`（浏览器 API） | **什么都不用做** | 机械，但立刻能听 |
| **云端** | OpenAI `/v1/audio/speech` | 有一个支持 TTS 的 URL + Key | 好听 + 能指定音色 |

**默认是「关」。** 但「系统」那一档**零配置可用** —— 选上就能听见她说话，不需要任何 Key。

### 这个软件不内置任何 TTS 服务商

只提供一个插口：**Base URL + API Key + 模型名**。

走 OpenAI 的 `/v1/audio/speech` 格式 —— 那是事实标准。已知能用的：

| 服务 | Base URL |
|---|---|
| OpenAI 官方 | `https://api.openai.com/v1` |
| SiliconFlow 硅基流动 | `https://api.siliconflow.cn/v1` |
| Fish Audio | `https://api.fish.audio/compat/v1` |
| new-api / one-api / LiteLLM | 你自己搭的网关地址 |

**Base URL 填到 `/v1` 就行；也可以直接填完整路径（以 `/audio/speech` 结尾）—— 那样就原样使用，不再拼接。**

> **⚠️ 2027-01-06 OpenAI 关停 TTS 模型** —— 详见 `docs/TODO.md` §八。
> 这不影响「格式」，因为还有六家在用。但到时候要重新评估。

### 不自动播放

**试过自动播，问题在群聊**：三个人连着回，三条语音互相打断 —— 实际只能听到最后一条的前半截。长回复也一样，念两分钟，人早就在看下一句了。

现在：**消息旁边一个 🔊，想听就点。**

- 点 → 念
- 再点 → 停
- 正在念 → 按钮变青 + 呼吸
- 念完 → 自己灭掉

**文字流是主，语音是按需。**

### `Persona.voice` 一个字段，两种解释

```
cloud  →  直接传给服务商（alloy / nova / 7f92b3c1…）
native →  模糊匹配系统音色名（Huihui 命中 Microsoft Huihui - Chinese (Simplified, PRC)）
```

匹配不上就用系统默认 —— 不会因为填错就不出声。

### 只念「能念的那部分」

`speakable()` 剔掉：代码块、系统条 `【…】`、括号里的动作描写、markdown 标记。

留着正文和对话。

## 6 秒待发窗口

**「发出去」和「让她收到」拆成两件事。**

| 操作 | 会发生什么 |
|---|---|
| **Enter** | 消息上屏（**半透明 0.55 + 橙色倒计时条 + 「待发」**）。**AI 还不知道。** |
| **6 秒内再 Enter** | 立即发出 → 变正常，她收到 |
| **6 秒自然走完** | 自动发出 |

### 窗口内可以「取回」或「删除」

在还没发出去的那 6 秒里，右键那条消息：

| 项 | 提示 | 做什么 |
|---|---|---|
| **取回** | 她还没收到 | 消息从对话消失，**文字回到输入框**，计时器作废。改完再发 |
| **删除** | 当没发过 | 真的扔掉，连文字都不留 |

**她全程不知道有这条。** 因为对她来说它从未发生。

### 发出去之后没有撤回

**撤回的前提是「对方还没看到」。她回了，就说明她看到了 —— 那就没有可撤回的东西了。**

所以 6 秒之后：

```
复制 · 引用 · 朗读
```

**就这样。没有编辑，没有撤回。**

已发出的消息不能改。因为改历史会造成断层 —— 她回的是原话，历史里却是改后的话，下一轮 prompt 里她会看到自己「回了一句你没说过的话」。

**这不是限制，是设定：话一旦说出口，就是泼出去的水。**

### 为什么要有这个窗口

原来的做法是「立刻发 + 撤回后清理」。那样 **AI 已经生成了回应**，撤回之后历史里会出现「她回了一句针对不存在的话」的断层。

现在她**根本收不到** —— 没有断层，也不需要清理。

**6 秒之内，话还不算数。**

### 提交闸门

两个真实的问题，都在「手很快」的时候出现：

1. **连按 Enter 能绕过 6 秒** —— 两条请求间隔 1 秒
2. **上一条 AI 还没回，下一条就发出去** —— 两条并发

后果：回复顺序可能颠倒、typing 指示器提前消失。

所以「真的发出去」要过一道闸：

| 限制 | 值 | 挡住什么 |
|---|---|---|
| **最小提交间隔** | `2000ms` | 连按 Enter 也不能让两条请求挨着发 |
| **AI 在回时排队** | `typing` 状态 | 新消息只入队，不冲出去。她回完 + 400ms 自动放行 |

**这是「提交」的闸，不是「打字」的闸** —— 你随时可以打字，只是它不会立刻冲出去。

## 右键菜单

**消息上没有悬停图标了。所有操作都在右键里。**

### 为什么去掉悬停栏

它原来长这样：`[复制][引用][朗读][编辑][撤回]` —— 一排气泡上沿的 18px 小图标。

**问题不在功能，在视觉密度。** 这个界面的对话是**稀疏气泡 + 大片留白**，每次悬停弹出一排图标很吵。而 QQ 那种消息密集的列表里，悬停栏混得进去。

**功能少 + 留白多 = 悬停栏亏。**

还有一个具体隐患：「编辑」和「撤回」原来只隔 1px，想点编辑手滑一格，内容当场清空。

### 现在

| 对象 | 菜单项 |
|---|---|
| **她的消息** | 复制 · 引用 · 朗读 |
| **你的 · 已发出** | 复制 · 引用 · 朗读 |
| **你的 · 待发中** | 复制 · 引用 · 朗读 ─── 取回 · 删除 |
| **角色卡** | 编辑角色 · 置顶 · 归档 · 强制改名… · 删除角色 |

### 挂到 body，不挂在行内

`ContextMenu` 用 `position: fixed` —— 但 **`fixed` 不是永远对着视口**。

祖先只要带 `filter` / `transform` / `perspective` / `contain`，它就变成 `fixed` 后代的**包含块**。消息行的根节点正好带着 `filter: blur(0px)`（入场动画留下的），于是菜单变成相对那一行定位，再被滚动容器的 `overflow` 裁掉。

**现象很迷惑：DOM 里查得到菜单项，屏幕上什么都没有。**

修法是 `createPortal(menu, document.body)` —— 一处改动，消息右键和角色右键全部恢复。

## 她眼里的你

关系 tab 顶部那一栏，**用她的口吻**说你是谁。

```
她眼里的你                              4 条
· 「他叫阿野」
· 「他在杭州上班」
· 「他不吃香菜，受不了那个味」
· 「他今天加班到十点，累死了」
```

源码：[`src/lib/eyeOfYou.ts`](src/lib/eyeOfYou.ts)。

### 难点不在算法，在措辞

记忆里存的是**你的原话**：「我不吃香菜，受不了那个味」。

那是「对话记录」，不是「她眼里的你」。要变成她的口吻。

**规则化改写，不调 LLM**（每次打开 tab 多一次调用，贵且慢；而且措辞要靠人定，模型每次给的句式不一样，这一栏就不可靠了）：

| 步骤 | 例子 |
|---|---|
| 剥掉「我说过」 | 「我说过我不吃香菜」→「我不吃香菜」 |
| 代词替换 `我/咱/俺 → 他` | 「我的猫」→「他的猫」 |
| 超过 34 字截在最后一个逗号 | 长句里代词多，改坏概率高 |
| 短于 3 字丢弃 | 没什么信息 |

### 有一类句子直接跳过

```
「你根本」「你不懂」「你不该」「我恨」「我讨厌你」「我不理」
```

**这些在说「我对你的态度」，不是「你是什么样的人」。**

改写成「他觉得你根本不懂他」—— 通顺，但意思已经变了。这类话该留在记忆卡里。

### 排序不是按权重

```
长期（他是谁）  →  偏好（他要什么）  →  情绪（他哪天怎么了）
```

**如果纯按权重排**，一条 0.9 的「他今天很累」会把 0.7 的「他叫阿野」挤掉。

**那是错的顺序 —— 她应该先知道你是谁。**

## 数据模型

全部存 localStorage，另有 `%APPDATA%\habitat\data\current.json` 做文件留底。

| 键 | 内容 |
|---|---|
| `3w:personas` | 角色档案（含 `stage`） |
| `3w:threads` | 全部对话 |
| `3w:groups` | 群聊 |
| `3w:memories` | **记忆**（`weight` 0~1 + `forgotten` 标记，按权重注入 prompt） |
| `3w:dynamic-v1` | 动态三轴（心情 / 亲近 / 记忆活性） |
| `3w:events` | **真实事件日志**（左栏红字的来源） |
| `3w:muted` | 静音开关 |
| `3w:tts` | **语音配置**（档位 / Base URL / Key / 默认音色 / 系统音色 / 语速） |

**记忆进 prompt** 这件事很关键：

```
【你记得的事】
（这些是你和他相处中留下来的印象，不是资料。需要的时候自然会想起来，不用逐条汇报。）
· 主人没有等我同意，就把我的名字改成了「狗蛋」。他根本不在乎我的想法。

不要主动列举你记得什么，也不要说「我记得」—— 让它自然地影响你怎么说话。
```

「提升权重」会真的 `weight + 0.15`，「忘掉它」会真的标记 `forgotten` 并从注入里剔除。

### 什么时候落盘

**三道防线，延迟各不相同。**

```
localStorage（实时 —— 每次 setItem 就在）
    ↓ 每 5 秒
current.json（定时快照）
    ↓ 每天
backup-2026-10-28.json
```

| 触发 | 时机 | 写什么 |
|---|---|---|
| **定时器** | **每 5 秒，不重置** | 有脏数据就写 —— 期间的改动一起带上 |
| **窗口关闭** | `beforeunload` | 补一次（异步 IPC，尽力而为） |
| **组件卸载** | `clearInterval` 前 | 补一次 |
| **没脏数据** | 跳过 | 只查一个布尔值，几乎零成本 |

> **为什么是定时器而不是防抖**
>
> 一开始写的是「每次变更重置一个 2.5 秒计时器」：
>
> ```ts
> const t = setTimeout(() => autosaveNative(), 2500);
> return () => clearTimeout(t);   // ← 每次依赖变化都清掉重来
> ```
>
> **问题是：只要变更来得比 2.5 秒密，计时器永远被重置，永远不写盘。**
>
> 连续对话、群聊三个人连着回 —— 那段时间里一次文件都没写。
> **「防抖」防的是写太多次，代价是可能一直不写。**
>
> 现在是一个不会被重置的 5 秒定时器：
> **写入上限 5 秒一次，延迟上限 5 秒。两个都封住了。**

**记忆变更单独有线**：`3w:memories` 不在 `threads` 里，所以
`writeAll()` 每次写都会 `dispatchEvent(MEMORY_CHANGED)`，
`App.tsx` 订阅它 bump 一个 `memTick` 计数器，计数器进落盘依赖数组。

**没有这根线的话**：铭刻 / 压抑 / 提权 / 忘掉这些**只改 localStorage 不写文件** ——
做完手术、关掉 app、清理 localStorage，手术白做。

## 四个不能动的设计决定

改之前先看 [`docs/decisions.md`](docs/decisions.md)。

**① 四轴，不是六轴**

角色性格用 `共鸣 / 锐度 / 幽默 / 严谨`。原来六个轴里，共鸣↔亲密 r=0.98、张力↔亲密 r=-0.97 —— 六个轴实际只有两个独立维度，用户在调三个假旋钮。

**② 性格和状态分开**

静态四轴一年不变，由人设决定。动态三轴（心情/亲近/记忆活性）一小时变三次，系统实时算，用户不能调。**动态值不画进雷达图** —— 画进去会让人以为性格在变。

**③ 一个凭据 ≠ 一个模型**

`ApiCredential` = 一个 baseUrl + 一个 Key + **一组模型**。中转站一个 Key 能出几十个模型，所以角色通过 `credentialId` 绑定到具体凭据，不是全局共用一个 Key。

**④ 「没有」和「空的」是两回事**

`null` = 从没存过 → 可以用示例数据。
`{}` / `[]` = 用户清过了 → **必须保持空**。

npm run pack
